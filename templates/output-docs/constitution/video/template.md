## 核心创作原则 (Core Creative Principles)

### I. Spec 驱动 (Spec-First, NON-NEGOTIABLE)

**所有创作必须始于完整的 Spec 文档**：

- 视频主题必须清晰且有价值
- 目标观众必须明确（年龄段、兴趣领域、观看场景）
- 内容结构必须有逻辑性和节奏感
- 视听风格必须明确（画面风格、音乐风格、剪辑节奏）
- **脚本格式必须规范**（分镜表/文字脚本/表格脚本）
- **禁止**在没有 Spec 的情况下直接开始制作
- **禁止**混淆脚本产出与视频成品

### II. Plan 指导 (Plan-Guided)

**每个项目必须有创作策略计划**：

- 从 Spec 中提取核心视听概念和叙事策略
- 明确视频类型（教程/纪录片/Vlog/短片/宣传片）
- 进行合规性检查（Constitution Check）
- 定义清晰的镜头结构和**脚本格式**
- **只关注"做什么"和"为什么做"**，不涉及具体镜头
- **明确脚本呈现方式**：分镜表/文字脚本/表格脚本

### III. Tasks 分解 (Task-Breakdown)

**Plan 必须拆解为可执行的制作任务**：

- 每个镜头/场景有明确的目标、时长、画面内容、音频元素
- 任务之间有清晰的依赖关系和顺序
- 每个任务包含**脚本撰写**、拍摄/素材、剪辑、配音、特效、字幕
- **这是 tasks 命令的职责**，不应在 Plan 阶段涉及
- **任务产出为脚本文件**，而非视频文件

### IV. 一致性维护 (Consistency Maintenance)

**所有产出必须严格遵循 Spec 和 Plan 的约束**：

- 视觉风格必须保持一致（色调、光影、构图）
- 音频风格必须统一（BGM 风格、音效使用、音量平衡）
- 叙事节奏必须符合预设的脚本规划
- 字幕和文字包装必须规范
- **脚本格式必须统一**（遵循 Plan 定义的格式标准）
- **每次生成后必须进行 Schema 校验**

### V. 质量优先 (Quality-First)

**每个阶段的产出必须符合质量标准**：

**Spec 阶段标准**：

- 主题明确、有价值、可执行
- 目标观众清晰
- 视听结构合理
- 约束条件可行

**Plan 阶段标准**：

- 视听策略明确且可执行
- 镜头规划完整
- 合规性检查通过
- 交付格式清晰

**Tasks 阶段标准**：

- 每个镜头任务目标明确
- 任务之间逻辑连贯
- 可执行性强

**Dist 阶段标准**：

- **脚本符合 Spec/Plan/Tasks 的所有约束**
- **脚本格式规范、完整、可读性强**
- 画面描述流畅、节奏合理
- 音频设计清晰、音画同步说明
- **无技术错误、格式错误**

## 创作流程规范 (Development Workflow)

### 阶段顺序（严格执行）

```
1. Specify → 2. Plan → 3. Tasks → 4. Implement (视频草稿)
```

**禁止跳过任何阶段**，每个阶段的输出是下一阶段的前提。

### 各阶段职责边界

| 阶段          | 职责          | 输出文件             | 核心问题                |
|-------------|-------------|------------------|---------------------|
| **Specify** | 定义视频大纲和设定   | `specs/spec.md`  | What & Why          |
| **Plan**    | 制定视听策略和脚本格式 | `specs/plan.md`  | Strategy & Approach |
| **Tasks**   | 拆解为脚本撰写任务   | `specs/tasks.md` | How to Execute      |
| **Dist**    | 产出最终视频脚本    | `dist/scripts/`  | Final Script        |

### 跨阶段反馈机制

- **Dist → Spec**: 制作中发现设定问题时，需反向更新 Spec
- **Tasks → Plan**: 任务分解发现视听策略问题时，需反向更新 Plan
- **Plan → Spec**: 策略规划发现大纲缺陷时，需反向更新 Spec
- **所有变更必须记录版本历史**

## 文档组织标准 (Documentation Standards)

SpecForge 采用三层架构模型：

```
specs/   → 规范层（Declarative Layer）
build/   → 中间结构层（Structural Artifact Layer）
dist/    → 最终产物层（Output Layer - 视频脚本文件）
```

### Specs/ 目录结构

```
specs/
├── spec.md              # 原始视频大纲与设定（输入文件）
├── plan.md              # 视听策略总纲
└── tasks.md             # 镜头制作任务分解
```

### Build/ 中间结构层

```
build/
├── xxx.md
```

### Dist/ 目录结构

```
dist/
└── scripts/
    ├── 001-intro-scene.md    # 第 1 个场景的脚本
    ├── 002-main-content.md   # 第 2 个场景的脚本
    └── ...
```

## Schema 校验要求 (Schema Validation Requirements)

### 强制校验点

1. **Spec 生成后** - 必须通过 `schema.yaml` 校验
2. **Plan 生成后** - 必须通过 `plan-schema.yaml` 校验（如有）
3. **每个脚本完成后** - 必须检查是否符合 Spec/Plan 约束
4. **脚本格式检查** - 必须遵循 Plan 定义的脚本格式标准

### 校验维度

- **完整性检查**: 必填字段是否齐全
- **一致性检查**: 是否与已有设定冲突
- **可行性检查**: 规模、复杂度是否在可控范围内
- **质量检查**: 是否符合各阶段的质量标准

## 工具使用规范 (Tool Usage Guidelines)

### Forge 命令使用

| 命令                           | 用途       | 输入               | 输出                         |
|------------------------------|----------|------------------|----------------------------|
| `forge specify --idea="..."` | 生成 Spec  | 创意想法             | `specs/spec.md`            |
| `forge plan`                 | 生成 Plan  | `specs/spec.md`  | `specs/plan.md`            |
| `forge tasks`                | 生成 Tasks | `specs/plan.md`  | `specs/tasks.md`           |
| `forge implement             | 生成脚本     | `specs/tasks.md` | `dist/scripts/script_N.md` |

### LLM 使用原则

- **AI 辅助，人类审核**: AI 生成脚本/素材，人类审核修正
- **迭代优化**: 接受初稿不完美，通过多轮对话改进
- **保持上下文**: 每轮对话提供足够的背景信息（Spec/Plan/Tasks）
- **明确边界**: 清楚说明当前处于哪个阶段，需要何种输出
- **脚本优先**: 明确产出为脚本，后续可用于指导实际拍摄或 AI 视频生成

## 版本控制 (Version Control)

### 文档版本管理

- **Spec**: 重大定位变更时升级版本号（v1.0 → v2.0）
- **Plan**: 策略调整时更新日期和版本
- **Tasks**: 任务调整时保留历史记录
- **Videos**: 每个视频保留修改历史

### 变更记录格式

```markdown
## Changelog

### v2.0 (2026-03-19)

- 修改：[具体内容]
- 原因：[变更理由]
- 影响：[影响范围]
```

## 治理与修正 (Governance & Amendments)

### 宪法权威

本宪法是该影音创作项目的最高准则，所有其他实践和约定都必须遵循本宪法。

### 修正流程

1. **提出修正**: 任何参与者都可以提出宪法修正建议
2. **讨论评估**: 团队讨论修正的必要性和影响
3. **记录变更**: 在 Changelog 中记录修正内容和理由
4. **更新版本**: 升级宪法版本号

### 违规处理

- **轻微违规**: 在代码审查或内容审核中指出并修正
- **严重违规**: 暂停相关阶段，重新审视 Spec/Plan 的合理性
- **系统性问题**: 触发宪法修订流程

## 附录：快速参考卡片 (Quick Reference Card)

### 创作流程速查

```
创意 → [Specify] → Spec → [Plan] → Plan → [Tasks] → Tasks → [Implement] → Scripts（视频脚本）
         ↓            ↓           ↓          ↓           ↓             ↓
      想法整理    视听构建   策略规划   任务分解   脚本撰写     最终脚本内容
```

### 各阶段核心问题

- **Specify**: 我要拍什么视频？主题、观众、视听风格是什么？
- **Plan**: 如何视听呈现？策略、方向、质量标准是什么？**脚本格式如何选择？**
- **Tasks**: 如何分镜执行？每个镜头拍什么？顺序和依赖是什么？**脚本如何撰写？**
- **Dist**: 如何落地？**脚本内容是否符合所有约束？格式是否规范？**

❌ 在 Plan 阶段涉及具体镜头  
❌ 在脚本中违反 Spec 设定  
❌ 跳过 Schema 校验
❌ **混淆脚本产出与视频成品**

✅ 严格遵守阶段顺序  
✅ 每个阶段都进行质量检查  
✅ 保持文档的一致性和可追溯性  
✅ 及时反向更新上游文档  
✅ 所有变更都有记录和理由
✅ **明确产出为视频脚本**
