## User Input

```text
$ARGUMENTS
```

**必须**在继续之前考虑用户输入（若不为空）。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目：检查 `.specforge/` 目录是否存在
2. 执行 `specforge show --paths-only` 获取当前活动 feature 路径：
   - 提取 `FEATURE_DIR`、`SPEC_FILE`、`IMPL_PLAN`
   - 若任一为空，ERROR：无法确定 feature 上下文
3. 确认规格文件存在：`SPEC_FILE`
4. 确认计划文件存在：`IMPL_PLAN`
5. 确认输出目录存在：检查 `dist/{content_type}/` 下是否有实际产出文件
   - 执行 `specforge show --artifact plan` 加载 plan.md 提取 `content_type`
   - 检查 `dist/{content_type}/` 目录下是否存在 .md 文件
   - 若为空，ERROR：实施产物缺失，请先执行 `/specforge.implement`
6. 读取 `.specforge/constitution.md` 加载宪法原则用于合规检查

## Outline

目标：将实施产物与原始规格和计划进行比对，从创作质量和需求满足度两个维度进行审查，生成结构化审查报告。

### 第 1 步：加载审查上下文

1. 执行 `specforge show --artifact spec` 加载规格
   - 提取创作目标和受众
   - 提取所有成功标准
   - 提取内容规模指标
   - 提取假设与约束

2. 读取 `FEATURE_DIR/plan.md`
   - 提取内容结构设计
   - 提取阶段规划和创作上下文
   - 提取资源约束

3. 扫描 `dist/{content_type}/` 目录
   - 列出所有产出文件
   - 将文件内容加载用于质量评估

4. 读取 `.specforge/constitution.md`（若存在）
   - 提取创作原则用于合规检查

### 第 2 步：成功标准评估

逐条比对规格中的成功标准与产出内容：

```markdown
| 序号 | 成功标准 | 状态 | 证据/说明 |
|------|----------|------|-----------|
| SC-1 | [标准描述] | ✅ / ⚠️ / ❌ | [评估依据] |
```

- ✅ 满足：产出明确达标
- ⚠️ 部分满足：产出接近达标但有提升空间
- ❌ 未满足：产出未达标准，需记录差距

### 第 3 步：创作质量评估

从以下维度评估产出质量：

#### 内容完整性

- 是否覆盖了规格中定义的所有创作场景？
- 是否有遗漏的关键章节/段落/场景？
- 内容规模是否在规格定义的范围内？

#### 结构一致性

- 产出结构与 plan.md 的设计是否一致？
- 章节/段落/分镜/场次的顺序和逻辑是否合理？
- 术语和风格在全文是否一致？

#### 可读性与受众适配

- 语言风格是否符合目标受众？
- 内容节奏和信息密度是否恰当？
- 是否存在明显的拼写、语法或格式问题？

#### 宪法合规性

- 产出是否遵循 `.specforge/constitution.md` 中的创作原则？
- 质量门禁是否通过？

### 第 4 步：识别改进项

生成结构化改进建议，按严重度分类：

- **CRITICAL**：阻塞发布的问题（严重违反成功标准或宪法）
- **HIGH**：影响质量但可发布（内容明显不足，结构偏差）
- **MEDIUM**：值得改进但不阻塞（风格不一致，细节欠缺）
- **LOW**：锦上添花（措辞微调，可选增强）

每条改进项格式：

```markdown
| ID | 严重度 | 类别 | 位置 | 问题描述 | 建议 |
|----|--------|------|------|----------|------|
| R1 | HIGH | 完整性 | 第3章 | 缺少关键情节转折 | 增加 [具体建议] |
```

### 第 5 步：生成审查报告

输出完整的结构化审查报告：

```markdown
# 创作审查报告：[功能名称]

**审查日期**：[日期]
**审查对象**：`dist/{content_type}/`
**规格引用**：SPEC_FILE
**计划引用**：IMPL_PLAN

## 1. 概述

- 输出文件数：[N]
- 总内容量：[字数/页数/时长]
- 审查结论：通过（有条件/无条件）/ 需修订 / 未通过

## 2. 成功标准评估

[第 2 步表格]

## 3. 创作质量评估

- 内容完整性：[评级 + 说明]
- 结构一致性：[评级 + 说明]
- 可读性与受众适配：[评级 + 说明]
- 宪法合规性：[评级 + 说明]

## 4. 改进项

[第 4 步表格]

## 5. 总量统计

- 成功标准：N 满足 / M 部分满足 / K 未满足
- CRITICAL 问题：[N]
- HIGH 问题：[N]
- MEDIUM 问题：[N]
- LOW 问题：[N]

## 6. 审查结论

- 若 0 CRITICAL 且所有成功标准 ≥ ⚠️：建议发布
- 若存在 CRITICAL：建议回溯修订后重新审查
- 若有 HIGH 问题：建议在发布前修复

## 7. 后续操作

- [建议的命令和操作]
```

### 第 6 步：输出报告

- 将审查报告输出到控制台（Markdown 格式）
- 同时写入 `FEATURE_DIR/review.md` 供存档
- 若有 CRITICAL 问题，询问用户是否需要回溯修复
- 若无问题或仅有低级别问题，确认可以完成 SDD 循环

## Output

- **审查报告**：`FEATURE_DIR/review.md`
- **格式**：Markdown，包含成功标准评估 + 质量评估 + 改进项 + 结论
- **控制台输出**：完整报告（用于即时审查）

## Stage Checkpoints

- [ ] 规格中的成功标准已逐条评估
- [ ] 所有输出文件已加载并检查
- [ ] 内容完整性、结构一致性、可读性、宪法合规性四维度均已评估
- [ ] 改进项已分类严重度（CRITICAL/HIGH/MEDIUM/LOW）
- [ ] 审查结论明确（发布/修订/未通过）
- [ ] 审查报告已写入 FEATURE_DIR/review.md

## 质量门禁

- 所有成功标准是否都获得了明确的评估结果（✅/⚠️/❌）？
- 创作质量评估是否涵盖了完整性、一致性、可读性、合规性四个维度？
- 改进项是否有具体的严重度分级和明确的修改建议？
- 审查结论是否直接关联到严重项的数量和分布？
- 所有 CLI 调用是否使用了 `--json` 参数（如适用）？
- 本文件中是否**不包含** git、branch、commit、hook 相关引用？

**后续**：SDD 循环完成。可根据审查结论决定发布、修订或进入下一个功能的 SDD 循环。

## 内容类型特定审查维度

根据内容类型，审查应额外关注以下维度：

### 小说审查
- **情节连贯性**：情节线是否无断裂，转折是否合理铺垫？
- **人物一致性**：人物行为和性格是否在章节间一致？
- **节奏评估**：叙事节奏是否符合目标读者预期？
- **世界观完整性**：设定细节是否前后一致？

### 文章审查
- **逻辑一致性**：论证链是否无跳跃或循环论证？
- **引用准确性**：参考文献是否均可查证且相关？
- **可读性**：段落长度和信息密度是否适合目标受众？

### 漫画审查
- **画面连贯性**：分镜过渡是否流畅，角色设计是否一致？
- **图文配合**：对话和画面的信息互补是否合理？
- **节奏控制**：翻页节奏和画面密度是否匹配阅读习惯？

### 视频审查
- **节奏一致性**：镜头时长和转场是否符合风格基调？
- **对话自然度**：台词是否符合角色和场景氛围？
- **视听配合**：画面描述是否足够支撑后续制作？

## 审查行为规则

- 审查是 **只读评估** ——不修改任何产出文件
- 若有 CRITICAL 问题，询问用户是否需要回溯修复
- 若无问题或仅有低级别问题，确认可以完成 SDD 循环
- 审查报告同时输出到控制台和 `FEATURE_DIR/review.md`
- 每次审查生成新报告，覆盖之前版本
