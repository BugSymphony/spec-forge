## User Input

```text
$ARGUMENTS
```

**必须**在继续之前考虑用户输入（若不为空）。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目：检查 `.specforge/` 目录是否存在
2. 执行 `specforge validate --stage tasks --json` 验证任务阶段完成：
   - 若验证失败，ERROR：任务阶段验证失败，请先完成 `/specforge.tasks`
   - 解析 JSON 输出，获取 `FEATURE_DIR` 和可用文档列表
3. 确认必需文件存在：
   - `FEATURE_DIR/spec.md` — 若缺失，ERROR：规格文件缺失
   - `FEATURE_DIR/plan.md` — 若缺失，ERROR：计划文件缺失
   - `FEATURE_DIR/tasks.md` — 若缺失，ERROR：任务文件缺失
4. 执行 `specforge show --paths-only` 获取所有路径变量
5. 读取 `.specforge/constitution.md` 加载宪法原则

## Outline

目标：在实施前识别 spec.md、plan.md、tasks.md 三个核心制品间的不一致、重复、歧义和定义不足。

### 操作约束

**严格只读**：绝不修改任何文件。输出结构化分析报告。提供可选的修正建议（用户必须在任何编辑操作前明确批准）。

**宪法权威**：项目宪法 `.specforge/constitution.md` 在本分析范围内**不可协商**。宪法冲突为自动 CRITICAL 级别，须调整规格、计划或任务——而非稀释、重新解释或忽略原则。

### 第 1 步：加载制品（渐进式披露）

仅加载每个制品的最少必要上下文：

**从 spec.md 加载**：
- 创作目标和概述
- 创作场景（全部）
- 成功标准（可度量成果）
- 核心要素
- 假设与约束
- 边缘场景

**从 plan.md 加载**：
- 创作上下文/技术方案
- 内容结构
- 阶段规划
- 资源约束

**从 tasks.md 加载**：
- 任务 ID 和描述
- 阶段分组
- [P] 并行标记
- 引用的文件路径
- [Scene] 标签

**从 constitution.md 加载**：
- 提取所有原则名称和其规范性声明

### 第 2 步：构建语义模型

创建内部表示（不在输出中包含原始制品全文）：

- **需求清单**：对每个创作场景和成功标准，记录稳定键值。使用场景标题或预期产出作为主键
- **任务覆盖映射**：将每个任务映射到一个或多个需求/场景（通过关键词或明确引用模式推断）
- **宪法规则集**：提取原则名称和规范声明

### 第 3 步：检测遍历（令牌高效分析）

聚焦高信号发现。限制 50 条发现总数，超出部分在溢出摘要中汇总。

#### A. 重复检测

- 识别近似重复的需求描述
- 标记冗余度更高的版本建议合并

#### B. 歧义检测

- 标记缺少可度量标准的模糊形容词（精彩、丰富、吸引人、强大）
- 标记未解决的占位符（TODO、???、`<placeholder>`、待定等）

#### C. 定义不足

- 有动词但缺少施用对象或可度量成果的需求
- 缺少验收标准对齐的创作场景
- 任务引用的文件或组件在 spec/plan 中未定义

#### D. 宪法对齐

- 与宪法原则冲突的任何需求或计划元素
- 宪法要求但缺失的章节或质量门禁

#### E. 覆盖缺口

- 没有关联任务的需求
- 没有映射的需求/场景的任务
- 需要可度量工作的成功标准在任务中无对应

#### F. 不一致

- 术语漂移（同一概念在不同文件中命名不同）
- plan 引用的实体在 spec 中缺失（或反之）
- 任务排序矛盾（如内容创作任务在基础设定任务之前）
- 冲突的需求（如一个要求每日更新，另一个要求每周打磨后再发布）

### 第 4 步：严重程度分级

使用以下启发式对发现进行优先级排序：

- **CRITICAL**：违反宪法规范声明、缺失核心制品、零覆盖的阻塞基础功能的需求
- **HIGH**：重复或冲突需求、安全/质量属性的歧义、不可测试的验收标准
- **MEDIUM**：术语漂移、缺失非功能性任务覆盖、定义不足的边缘场景
- **LOW**：措辞改善、不影响执行顺序的轻微冗余

### 第 5 步：生成紧凑分析报告

输出 Markdown 报告（不写入文件），结构如下：

## 规格分析报告

| ID | 类别 | 严重度 | 位置 | 摘要 | 建议 |
|----|------|--------|------|------|------|
| A1 | Duplication | HIGH | spec.md:L120-134 | 两条相似需求... | 合并措辞，保留更清晰的版本 |

（每发现一行；生成稳定 ID，以类别首字母为前缀）

**覆盖摘要表**：

| 需求键 | 有任务？ | 任务 ID | 备注 |
|--------|----------|---------|------|

**宪法对齐问题**：（若有）

**未映射任务**：（若有）

**指标**：
- 总需求数
- 总任务数
- 覆盖率%（有 ≥1 个任务的需求占比）
- 歧义数
- 重复数
- CRITICAL 问题数

### 第 6 步：提供下一步操作

在报告末尾输出简洁的下一步操作块：

- 若存在 CRITICAL 问题：建议先解决再执行 `/specforge.implement`
- 若仅有 LOW/MEDIUM：用户可继续执行，并提供改善建议
- 给出明确的命令建议："用修正重新运行 /specforge.specify"、"运行 /specforge.plan 调整结构"、"手动编辑 tasks.md 为 'xxx' 添加覆盖"

### 第 7 步：提供修正建议

询问用户："是否需要我为前 N 个问题提供具体修正编辑建议？"（不要自动应用）

## Output

- **制品**：只输出到控制台（Markdown 格式），**不写入任何文件**
- **报告内容**：发现表 + 覆盖摘要 + 宪法对齐 + 指标 + 下一步操作
- **限制**：最多 50 条发现，超出部分在溢出摘要汇总

- [ ] 每条发现已分配严重度等级和稳定 ID

- 分析是否为严格的只读操作——没有写入或修改任何文件？
- 是否对所有 6 个检测类别进行了系统性扫描？
- 宪法冲突是否全部标记为 CRITICAL 而未淡化？
- 覆盖分析是否涵盖了所有创作场景和成功标准？
- 报告是否紧凑高效（聚焦可行动发现，非详尽文档）？

## 分析准则

### 上下文效率

- **最少高信号令牌**：聚焦可行动发现，非详尽文档
- **渐进式披露**：增量加载制品；不将所有内容全部倾倒到分析中
- **令牌高效输出**：发现表限制 50 行；汇总溢出
- **确定性结果**：无变更重跑应产生一致的 ID 和计数

### 分析指南

- **绝不修改文件**（此为只读分析）
- **绝不虚构缺失的章节**（如实报告缺失情况）
- **优先处理宪法违规**（这些始终是 CRITICAL）
- **使用示例而非详尽规则**（引用具体实例，非通用模式）
- **零问题时优雅报告**（输出带覆盖率统计的成功报告）

### 内容类型特定检查

根据 plan.md 中的内容类型，额外关注以下方面：

**小说**：
- 人物关系数据模型是否与 spec 中的核心要素一致？
- 章节拆分计划的阶段数与 tasks 中的创作场景数是否匹配？
- 世界观设定是否在所有引用章节中一致定义？

**文章**：
- 论证逻辑链中的数据模型是否覆盖所有核心论点？
- 引用清单中的来源是否在 tasks 中有对应的验证任务？
- 段落大纲与 spec 的内容规模是否匹配？

**漫画**：
- 角色设计属性是否在 data-model 和 tasks 间一致定义？
- 分镜规划与内容规模的目标页数/话数是否对齐？
- 视觉风格约束是否在 spec、plan、tasks 中一致传达？

**视频**：
- 场景模型的属性是否覆盖所有 plan 中定义的场景类型？
- 台词的存储和版本管理是否在三个制品间一致？
- 分镜头模板的契约定义与 tasks 中的创作任务是否对齐？

### 严重度分配细节

- **CRITICAL**：违反宪法规范声明、缺失核心制品（spec/plan/tasks 任一缺失）、需求零覆盖阻塞基础功能
- **HIGH**：重复或冲突需求、内容质量属性的歧义、不可验证的验收标准、术语严重不一致导致执行混乱
- **MEDIUM**：术语漂移、缺失非功能任务覆盖、定义不足的边缘场景、数据模型不一致但不影响执行顺序
- **LOW**：措辞改善、不影响执行顺序的轻微冗余、格式建议
