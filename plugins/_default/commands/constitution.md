# 项目宪法管理

## User Input

```text
$ARGUMENTS
```

根据用户输入创建或修改 `.specforge/constitution.md` 宪法文件。宪法是 SpecForge SDD 工作流的基石，定义了项目的核心创作原则、质量标准和治理规则。所有后续阶段的命令在执行时必须遵循宪法约束。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目（存在 `.specforge/` 目录）
2. 执行 `specforge list --detail --json` 确认当前活动 feature 和项目上下文
3. 读取 `.specforge/templates/constitution-template.md` 作为输出结构参考
4. 若 `.specforge/constitution.md` 已存在，视为更新操作——保留已有原则，仅根据用户输入调整或补充

## Outline

### 第 1 步：解析用户输入

- 从 `$ARGUMENTS` 中提取关键信息：
  - **创作领域**：项目的内容类型（{content_type_cn}）、目标受众、创作方向
  - **核心原则**：用户明确提出的不可妥协的创作理念或限制
  - **质量标准**：用户提到的验收标准、发布要求
  - **治理规则**：协作方式、修订流程、版本管理偏好
- 若用户输入为空，ERROR：提示用户提供创作项目的目标描述或核心原则，例如 "本项目为面向青少年的科幻小说系列，注重科学准确性和角色成长"

### 第 2 步：加载宪法模板

- 读取 `.specforge/templates/constitution-template.md` 获取结构
- 模板包含以下章节：
  - `# [PROJECT_NAME] 创作宪法`
  - `## 核心原则`（含 `### [原则名称]`、描述和 `**理由**`）
  - `## 质量标准`（含 `QS-###` 编号）
  - `## 治理规则`（修订流程和版本管理）

### 第 3 步：定义核心原则（最少 3 条）

引导用户定义 3-5 条核心创作原则。使用以下引导问题：

1. **第一条原则（最重要）**：这个项目最不可妥协的创作理念是什么？
   - 例如：小说 → "情节推动必须由角色决策驱动，禁止依赖巧合"
   - 例如：漫画 → "每个分镜必须服务于情绪传达，禁止无意义的过渡格"
   - 例如：视频 → "所有镜头语言必须符合设定的风格基调"
2. **第二条原则**：内容的差异化或独特价值在哪里？
3. **第三条原则**：质量的最低标准是什么？（具体到可验证）
4. **第四条原则（可选）**：协作或流程上的约束？
5. **第五条原则（可选）**：对受众的承诺？

每条原则包含三个部分：
- **原则名称**：简短摘要（1 句话）
- **描述**：具体说明（3-5 句），定义本原则的适用范围和判断标准
- **理由**：为什么这条原则对项目质量至关重要

若用户未明确提供足够信息，基于内容类型（{content_type_cn}）提供合理默认值，并标注为"建议原则——请审查确认"。

### 第 4 步：定义质量标准

列出适用于所有 SDD 阶段制品的质量检查维度，使用 QS-### 编号：

- **QS-001 完整性**：所有必填字段均已填写，无空占位符
- **QS-002 一致性**：上下游制品间无矛盾，术语统一
- **QS-003 可执行性**：任务描述具体可操作，含明确产出
- **QS-004 清晰性**：无歧义标记，成功标准可验证

若内容类型有特殊要求，追加类型特有标准：
- 小说 → QS-005 叙事连贯性：情节线无断裂，角色行为一致性
- 漫画 → QS-005 画面连贯性：分镜过渡流畅，角色设计一致
- 视频 → QS-005 节奏一致性：镜头时长和转场符合风格基调

### 第 5 步：设定治理规则

定义宪法的修订流程和版本管理：

**修订流程**：
1. **提议**：任何贡献者可提交修订提案，说明动机和影响范围
2. **审查**：维护者评估合理性和影响范围
3. **批准**：审查通过后合并修订
4. **传播**：同步更新依赖制品的宪法引用

**版本管理**：使用 MAJOR.MINOR.PATCH 语义版本

### 第 6 步：写入宪法文件

- 使用模板结构，用第 3-5 步的生成内容填充占位符
- 写入 `.specforge/constitution.md`
- 确保版本号设为 `1.0.0`，批准日期和最后修订日期为当前日期
- 若为更新操作：保留当前版本号，根据变更幅度递增（PATCH→措辞澄清，MINOR→新增原则、章节，MAJOR→移除或重新定义原则）

## Output

- **制品**：`.specforge/constitution.md`
- **格式**：Markdown
- **位置**：项目根目录 `.specforge/constitution.md`

## Stage Checkpoints

- [ ] 至少定义 3 条创作原则，每条有名称、描述和理由
- [ ] 质量标准至少涵盖完整性、一致性、可执行性、清晰性四类
- [ ] 版本号和日期已填写
- [ ] 宪法内容与内容类型（{content_type_cn}）对齐
- [ ] 无模糊占位符残留

## 质量门禁

- 原则条目中的描述是否具体到可判断是否违规？
- 质量标准是否涵盖所有 SDD 阶段制品的通用要求？
- 治理规则是否包含修订流程和版本管理？
- 内容类型特有要求是否已包含？

**下一步**：执行 `/specforge.specify` 基于本宪法编写功能规格
