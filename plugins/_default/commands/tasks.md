## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目：检查 `.specforge/` 目录是否存在
2. 执行 `specforge validate --stage plan --json` 验证计划阶段完成：
   - 若验证失败，ERROR：计划阶段验证失败，请先完成 `/specforge.plan`
   - 解析 JSON 输出，获取 `FEATURE_DIR` 和可用文档列表
3. 执行 `specforge setup tasks --json` 初始化任务环境：
   - 若失败，ERROR：任务环境初始化失败
   - 解析 JSON 输出，获取 `TASKS_FILE` 和 `TASKS_TEMPLATE` 路径
4. 确认所需文档可用：`FEATURE_DIR/plan.md`（必须）、`FEATURE_DIR/spec.md`（必须）

## Outline

目标：将规格和计划转化为按依赖关系排列的可执行任务清单，每个创作场景可独立实施和测试。

### 第 1 步：加载设计文档

从 `FEATURE_DIR` 读取：

- **必须**：`spec.md` — 提取创作场景及优先级（P1、P2、P3...）
- **必须**：`plan.md` — 提取创作上下文、内容结构、阶段规划、工具和存储方案
- **可选**：`data-model.md` — 实体模型（映射到创作场景）
- **可选**：`contracts/` — 接口契约（映射到创作场景）
- **可选**：`research.md` — 调研决策（用于准备任务）
- **可选**：`quickstart.md` — 测试/验证场景

### 第 2 步：提取并优先级排序创作场景

1. 从 `spec.md` 中解析所有创作场景，提取：
   - 场景标题和描述
   - Why This Priority 理由
   - Independent Test 条件
   - Given-When-Then 验收标准
   - 每个场景的优先级标记（P1 > P2 > P3...）

2. 按优先级排序：P1 场景最先实施以快速形成 MVP

### 第 3 步：生成任务（按创作场景组织）

**核心规则**：任务必须按创作场景分组，使每个场景可独立实施和验证。

#### 任务清单格式（必须严格遵守）

```text
- [ ] [TaskID] [P?] [Scene?] 描述含文件路径
```

**格式元素**：

1. **复选框**：始终以 `- [ ]` 开头（Markdown 复选框）
2. **任务 ID**：顺序编号（T001、T002、T003...）
3. **[P] 标记**：仅在任务可并行时添加（不同文件、不依赖未完成的任务）
4. **[Scene] 标签**：仅用于创作场景阶段的任务，格式为 `[S1]`、`[S2]`、`[S3]`
   - 准备阶段：无 Scene 标签
   - 基础阶段：无 Scene 标签
   - 创作场景阶段：必须有 Scene 标签
   - 打磨阶段：无 Scene 标签
5. **描述**：明确的操作及确切的文件路径

**示例**：
- ✅ `- [ ] T001 按创作计划创建项目目录结构`
- ✅ `- [ ] T005 [P] 编写世界观设定文件 specs/xxx/settings/world-setting.md`
- ✅ `- [ ] T012 [P] [S1] 起草第1章初稿 dist/novel/第1章-开端.md`
- ❌ `- [ ] 创建世界观`（缺少 ID 和 Scene 标签）
- ❌ `T001 [S1] 起草章节`（缺少复选框）
- ❌ `- [ ] [S1] 起草第1章`（缺少 Task ID）
- ❌ `- [ ] T001 [S1] 起草内容`（缺少文件路径）

#### 任务组织规则

1. **从创作场景组织（首要组织方式）**：
   - 每个创作场景（P1、P2、P3...）对应一个独立阶段
   - 将场景需要的所有工作映射到任务：
     - 该场景需要的设定/素材准备
     - 该场景需要的创作输出
     - 若需要验证：该场景的验证检查
   - 标记场景间依赖（大多数场景应相互独立）

2. **从契约映射**：
   - 每个接口契约 → 映射到对应场景阶段的实现任务
   - 接口契约 → 在实现前的准备任务（若需要）

3. **从数据模型映射**：
   - 每个实体 → 映射到需要它的场景
   - 若实体服务多个场景：放入最早场景或基础阶段
   - 关系 → 对应场景阶段的创作/检查任务

4. **从准备/基础映射**：
   - 共享准备 → 准备阶段（Phase 1）
   - 阻塞性前提任务 → 基础阶段（Phase 2）
   - 场景特定准备 → 对应场景阶段内

#### 并行任务标记规则

标记 `[P]` 仅当任务满足以下所有条件：
- 与同一阶段的其他 `[P]` 任务操作不同文件
- 不依赖本阶段任何未完成的非并行任务
- 可在不等待其他任务完成的情况下独立执行

**典型并行场景**：
- 多个独立的世界观设定文件同时编写
- 同一场景内的多个独立章节/段落同时起草
- 不冲突的修订/验证任务

### 第 4 步：构建阶段结构

#### Phase 1：准备（Setup）

项目初始化和环境配置：

- 确认目录结构符合计划中的约定
- 初始化创作工具配置
- 准备参考资料和设定文档
- 创建 `dist/{content_type}/` 输出目录

任务格式：`- [ ] T001 确认项目目录结构符合计划约定`（无 Scene 标签）

#### Phase 2：基础（Foundational）— 阻塞所有创作场景的前提

所有创作场景开始前必须完成的共享基础设施：

- 世界观/核心设定定稿（从 research.md / data-model.md 提取）
- 关键人物/论点/元素定义定稿
- 模板和规范文件准备
- 若有 data-model.md：将实体映射到共享设定文件

任务格式：`- [ ] T00N [P] 创建核心设定文件 specs/xxx/settings/core-setting.md`（含 [P]，无 [Scene]）

#### Phase 3+：创作场景（按优先级排序）

每个创作场景对应一个独立阶段，按 P1、P2、P3... 顺序排列：

**每个场景阶段包含**：
1. **场景目标**：简述本场景的核心创作目标
2. **独立测试标准**：如何验证本场景已完成
3. **创作任务**：按顺序排列的具体创作操作
4. **验收任务**：验证创作质量的检查项

**任务映射规则**：
- 从 data-model（若存在）→ 该场景需要的实体映射到任务
- 从 contracts（若存在）→ 每个接口契约映射到对应的实现任务
- 场景角色标签：[S1]、[S2]、[S3]...

#### Phase N：打磨（Polish）

跨场景的收尾工作：

- 全局一致性检查
- 修订和编辑
- 质量验收

任务格式：`- [ ] T0MM 全局修订：检查前后文一致性`（无 Scene 标签）

### 第 5 步：生成依赖关系表

在 tasks.md 中生成场景完成顺序依赖图。

```markdown
## 依赖关系

| 阶段 | 依赖 |
|------|------|
| Phase 2 (基础) | Phase 1 (准备) |
| Phase 3 (S1) | Phase 2 (基础) |
| Phase 4 (S2) | Phase 2 (基础) |
| Phase 5 (S3) | Phase 2 (基础) |
| Phase N (打磨) | Phase 3+ (所有场景) |
```

大多数创作场景应相互独立（依赖基础阶段但不互相依赖）。

### 第 6 步：写入 tasks.md

使用 `TASKS_TEMPLATE` 路径的模板作为结构（若模板为空，回退到 `.specforge/templates/tasks-template.md`）。填入：

- 正确的功能名称（从 spec.md 提取）
- 所有阶段和任务（按上述结构）
- 依赖关系表
- 实施策略：MVP 优先（建议仅完成 Phase 1-3 即可交付 MVP）

### 第 7 步：报告完成

向用户输出：

- **任务文件路径**：`TASKS_FILE`
- **总任务数**
- **每个创作场景的任务数**
- **识别的并行机会**
- **每个场景的独立测试标准**
- **建议的 MVP 范围**（通常仅场景 S1）
- **格式验证**：确认所有任务遵循检查清单格式（复选框、ID、标签、文件路径）

## Output

- **制品**：`FEATURE_DIR/tasks.md`
- **格式**：Markdown 检查清单，含 `- [ ] [TID] [P?] [Scene?] 描述含文件路径`
- **阶段**：Phase 1 准备 → Phase 2 基础 → Phase 3+ 创作场景 → Phase N 打磨

## Stage Checkpoints

- [ ] 所有 spec.md 中的创作场景已映射到任务阶段
- [ ] 每个场景阶段有完整的任务链（创建 → 验收）
- [ ] 依赖关系清晰：基础阻塞所有场景，场景间相互独立
- [ ] [P] 标记的任务确实可以并行执行
- [ ] 任务格式严格遵循 `- [ ] [TaskID] [P?] [Scene?] 描述含文件路径`
- [ ] 所有任务包含确切的文件路径

## 质量门禁

- 每个创作场景是否可独立实施和验证？
- 基础阶段是否包含所有场景的共享前提任务？
- 任务描述是否足够具体，不需额外上下文即可执行？
- 依赖关系是否合理，无循环依赖？
- 所有 CLI 调用是否使用了 `--json` 参数（如适用）？
- 本文件中是否**不包含** git、branch、commit、hook 相关引用？

**下一步**：执行 `/specforge.checklist` 生成领域质量检查清单，或执行 `/specforge.analyze` 进行一致性分析。

## 任务生成注意事项

- tasks.md 应立即可执行——每个任务必须足够具体，Agent 可直接完成无需额外上下文
- 测试类任务是可选的——仅当规格中明确要求或用户指定 TDD 方法时才生成
- 每个场景阶段应有完整的任务链：准备素材 → 创作内容 → 验收质量
- MVP 优先：Phase 1-3（准备 + 基础 + 场景 S1）为最小可交付范围
- 所有任务描述必须包含确切的文件路径——执行者无需猜测文件位置

### 内容类型特定任务模板

**小说章节写作任务**：
`- [ ] T0XX [S1] 撰写第N章初稿 dist/novel/第N章-标题.md`
`- [ ] T0XX [P] [S1] 核实第N章人物行为与设定一致性 against specs/xxx/settings/character-profiles.md`

**文章段落写作任务**：
`- [ ] T0XX [S1] 撰写引言段落 dist/article/标题.md — 引出核心论点`
`- [ ] T0XX [S1] 核对引用来源与 specs/xxx/design/reference-list.md 一致`

**漫画分镜任务**：
`- [ ] T0XX [S1] 起草第N话分镜脚本 dist/comic/第N话-脚本.md`
`- [ ] T0XX [P] [S1] 绘制角色参考草图 dist/comic/角色参考.md`

**视频场次任务**：
`- [ ] T0XX [S1] 编写第N集分镜头脚本 dist/video/第N集-分镜头脚本.md`
`- [ ] T0XX [P] [S1] 整理台词本 dist/video/台词本.md`
