## User Input

```text
$ARGUMENTS
```

**必须**在继续之前考虑用户输入（若不为空）。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目：检查 `.specforge/` 目录是否存在
2. 执行 `specforge show --paths-only` 获取当前活动 feature 的路径信息：
   - 提取 `FEATURE_DIR` 和 `SPEC_FILE`
   - 若解析失败，ERROR：无法确定当前 feature，请先执行 `/specforge.specify` 创建规格
3. 确认 `SPEC_FILE` 存在，若不存在则 ERROR：规格文件缺失，请先执行 `/specforge.specify`
4. 执行 `specforge show --artifact spec` 预加载规格内容，验证 Markdown 结构有效
   - 若规格文件损坏或格式异常，ERROR：规格文件无法解析，请检查文件完整性

## Outline

目标：检测并减少活动功能规格中的歧义和缺失决策点，将澄清记录直接写入规格文件。

注意：澄清工作流应在调用 `/specforge.plan` **之前**执行并完成。若用户明确表示跳过澄清（如探索性试验），可继续执行，但需警告下游返工风险增加。

### 第 1 步：加载当前规格

执行 `specforge show --artifact spec` 加载规格内容，构建内部语义模型：

- 解析所有章节：创作目标、内容规模、创作场景、核心要素、成功标准、假设与约束
- 提取已有决策和显式声明
- 标记存在歧义或信息缺失的区域

### 第 2 步：结构化歧义扫描

对规格进行 8 大分类的结构化覆盖率扫描。每个分类标记状态：明确 / 部分覆盖 / 缺失。

#### 分类 1：创作范围与行为
- 核心创作目标和成功标准是否明确？
- 显式排除的范围声明是否存在？
- 受众/读者角色是否已区分？

#### 分类 2：领域与数据模型
- 核心要素（人物/世界观/论点等）的属性、关系和唯一性规则是否定义？
- 内容生命周期和状态转换是否描述？
- 内容规模/体量假设是否说明？

#### 分类 3：交互与体验流程
- 关键创作流程/顺序是否定义？
- 异常/缺失/空加载状态是否考虑？
- 可访问性或本地化注意事项是否存在？

#### 分类 4：非功能性质量属性
- 创作节奏（更新频率、发布周期）是否有目标？
- 内容体量限制（字数、集数等）是否明确？
- 读者留存和阅读完播率等质量指标是否说明？
- 可观察性（版本跟踪、修订记录）是否有要求？
- 安全和隐私是否涉及（受众人身信息、内容版权）？

#### 分类 5：集成与外部依赖
- 是否依赖外部研究资料、参考资料或合作平台？
- 数据导入/导出格式是否明确？
- 协议/版本假设是否说明？

#### 分类 6：边缘场景与异常处理
- 负面/反常场景是否考虑？
- 内容冲突或矛盾（如人物设定冲突、情节矛盾）如何处理？
- 读者反馈和内容修订流程是否明确？

#### 分类 7：约束与权衡
- 明确的技术约束（特定平台、格式、工具）是否记录？
- 替代方案或排除选项是否说明？

#### 分类 8：术语与一致性
- 关键术语是否有统一定义？
- 是否存在同义词或易混淆表述？

### 第 3 步：生成优先问题队列

根据扫描结果生成优先级排序的候选澄清问题（内部使用，不同时输出）。规则：

- **最多 5 个问题**（整个会话总计）
- 每个问题必须能以下列方式之一回答：
  - 简短多选题（2-5 个互斥选项）
  - 简短短语（≤5 个词）
- 仅收录对创作结构、内容设计、任务分解、验证设计或质量评估有实质性影响的答案
- 确保分类覆盖平衡：优先处理最高影响的未解决分类
- 排除已在规格中回答的问题、无关紧要的风格偏好、或更适合计划阶段处理的信息
- 若超过 5 个分类未解决，按（影响力 × 不确定性）启发式选择前 5 个
- 若**没有**有意义的歧义，直接报告「未检测到需要正式澄清的关键歧义」并结束

### 第 4 步：交互式顺序问答

**每次仅呈现一个问题**。不要提前展示后续问题。

#### 多选题格式

分析所有选项，基于以下因素推荐最合适的选项：

- 该内容类型的最佳实践
- 同类项目的常见模式
- 风险降低（质量、一致性、可维护性）
- 与规格中已有的明确目标或约束的对齐

以 **推荐** 选项开头并附推理，然后以表格呈现所有选项：

```markdown
**推荐：** 选项 [X] — <1-2 句推理>

| 选项 | 描述 |
|------|------|
| A | <选项 A 描述> |
| B | <选项 B 描述> |
| C | <选项 C 描述>（最多到 E） |
| 简短 | 提供不同的简短答案（≤5 个词） |

您可以回复选项字母（如 "A"），说 "yes" 或 "推荐" 接受推荐，或提供自定义答案。
```

#### 简答题格式

提供**建议答案**并附简短推理（≤5 个词）。

```markdown
**建议：** <建议答案> — <简短推理>

格式：简短答案（≤5 个词）。您可以说 "yes" 或 "建议" 接受建议，或提供自己的答案。
```

### 第 5 步：增量集成答案

每接受一个答案后**立即**更新规格（原子覆盖保存）：

1. 若本会话首次集成：
   - 确保规格中存在 `## Clarifications` 章节（若缺失，在概述章节之后创建）
   - 在其下创建 `### Session YYYY-MM-DD` 子标题（当前日期）
2. 追加一条记录：`- Q: <问题> → A: <最终答案>`
3. 根据澄清类别更新对应规格章节：
   - 创作范围歧义 → 更新创作目标或假设与约束
   - 内容结构歧义 → 更新核心要素或内容规模
   - 质量属性歧义 → 更新成功标准（将模糊形容词转为具体指标）
   - 边缘场景 → 在假设与约束中添加新条目
   - 术语冲突 → 统一规格全文措辞
4. 若澄清使之前某个笼统表述失效，**替换**而非重复保留
5. 保持格式：不重排无关章节，保持标题层级完整
6. 每次集成后保存文件，最小化上下文丢失风险

### 第 6 步：验证

每次写入后及最终通过时执行验证：

- 澄清会话每条记录对应一个接受的答案（无重复）
- 总提问（接受）数 ≤ 5
- 更新后的章节无残留的模糊占位符
- 无矛盾的旧陈述残留（扫描并清理已失效的替代选项）
- Markdown 结构有效：仅允许的新标题为 `## Clarifications` 和 `### Session YYYY-MM-DD`
- 术语一致性：同一规范术语在所有更新章节中一致使用

### 第 7 步：报告完成

输出最终的澄清报告：

- **提问数和已回答数**
- **更新的规格文件路径**
- **触及的章节清单**
- **覆盖率摘要表**：每个分类的状态（已解决 / 延迟 / 明确 / 残留），含状态说明
- **下一步建议**：
  - 若有延迟或残留项（低影响），建议是否可继续 `/specforge.plan`
  - 若无任何未解决项，建议直接进入 `/specforge.plan`

## 行为规则

- 若未发现有意义歧义（或所有潜在问题都是低影响），回复：「未检测到需要正式澄清的关键歧义」并建议继续
- 若规格文件缺失，指示用户先运行 `/specforge.specify`（不要在此处创建新规格）
- 绝不超过 5 个总提问数（单个问题的澄清重试不计为新问题）
- 避免推测性内容类型问题，除非其缺失阻碍了功能性清晰度
- 尊重用户提前终止信号（"停"、"完成"、"继续"）
- 若因全面覆盖而未提问：输出紧凑的覆盖率摘要（所有分类为 Clear），建议进入 plan
- 若配额已用完但仍有未解决的高影响分类，明确在 Deferred 下标记并说明理由
- 回答验证规则：
  - "yes"/"推荐"/"建议" → 使用之前声明的推荐/建议作为答案
  - 选项字母（A/B/C）→ 使用对应选项的描述作为答案
  - 若答案模糊，要求快速消除歧义（仍计为同一问题，不推进）
  - 若答案与任一选项不匹配且非 ≤5 词 → 再次提示格式约束

## 内容类型特定扫描维度

根据当前内容类型，额外检查以下维度：

**小说**：
- 世界观设定的内部一致性规则是否定义？
- 人物成长弧线和行为动机是否有明确描述？
- 情节线索之间的交织关系是否说明？

**文章**：
- 核心论点和支撑论据的区分是否明确？
- 引用来源的可信度和最新性是否有要求？
- 反驳观点的处理策略是否涉及？

**漫画**：
- 角色视觉设计的一致性原则是否说明？
- 分镜节奏和页面翻页的阅读节奏是否有约束？
- 对话气泡和旁白的使用规范是否定义？

**视频**：
- 场景过渡和镜头语言的风格基调是否明确？
- 对白时长和画面节奏的对应关系是否有说明？

## Output

- **制品**：更新后的 `SPEC_FILE`（原地修改）
- **澄清会话**：`## Clarifications > ### Session YYYY-MM-DD` 下
- **格式**：Markdown，保持原有结构和标题层级

## Stage Checkpoints

- [ ] 8 大分类维度已完成覆盖率扫描
- [ ] 优先问题队列已生成（最多 5 个）
- [ ] 每个问题已顺序提问并接受答案
- [ ] 每个答案已增量集成到规格对应章节
- [ ] Clarifications 会话条目数与已回答问题数一致
- [ ] 规格中无矛盾的旧内容残留
- [ ] 术语在全文一致
- [ ] 覆盖率摘要表已输出

## 质量门禁

- 是否检测到并解决了对内容结构有实质性影响的歧义？
- 每个答案是否直接更新了对应规格章节（而非仅记录在 Clarifications 区）？
- 提问数是否 ≤ 5，且覆盖了最高影响的分类？
- 规格是否已准备好进入计划阶段（无阻塞性歧义）？
- 所有 CLI 调用是否使用了 `--json` 参数（如适用）？
- 本文件中是否**不包含** git、branch、commit、hook 相关引用？

**下一步**：执行 `/specforge.plan` 基于已澄清的规格创建创作计划。
