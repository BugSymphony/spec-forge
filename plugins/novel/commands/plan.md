# 小说实施计划编写

## User Input

```text
$ARGUMENTS
```

根据小说规格说明（`specs/<NNN>-<name>/spec.md`）创建实施计划（`specs/<NNN>-<name>/plan.md`）。小说实施计划聚焦于 **HOW**（怎么写）——包括章节拆分、人物弧线映射、情节节奏时间线、设计文档生成。

## Pre-Execution Checks

1. 确认当前活动 feature 目录存在（`specs/<NNN>-<name>/`）
2. 执行 `specforge setup plan --json` 初始化计划环境（复制模板、创建 build/ 目录）
3. 读取 `specs/<NNN>-<name>/spec.md` 作为计划输入——计划必须忠实于规格中定义的 WHAT/WHY
4. 读取 `.specforge/constitution.md` 确保计划遵循宪法中的文学原则和叙事标准
5. 读取 `plugins/novel/templates/plan.md` 作为输出结构参考
6. 确认 `specs/<NNN>-<name>/build/` 目录已创建，用于存放设计文档

## Outline

### 第 1 步：章节拆分设计

基于规格中的情节大纲（5 阶段）和内容规模（目标章节数、每章字数范围），设计详细的章节拆分方案：

#### 1.1 阶段→章节映射

将情节大纲的 5 个阶段映射到具体章节。每个阶段分配大致章节比例：

| 阶段 | 章节范围 | 估算占比 | 核心功能 |
|------|---------|---------|---------|
| 开端（建置） | 第1章 - 第N章 | ~15% | 世界观介绍 + 角色引入 + 冲突暗示 |
| 发展（上升行动） | 第N+1章 - 第M章 | ~35% | 冲突升级 + 角色成长 + 支线展开 |
| 转折（危机） | 第M+1章 - 第K章 | ~15% | 方向转变 + 重大揭示 |
| 高潮（对决） | 第K+1章 - 第J章 | ~20% | 核心冲突解决 |
| 结局（收束） | 第J+1章 - 第L章 | ~15% | 各线收束 + 最终状态 |

#### 1.2 逐章细纲

生成完整的章节细纲表，每章包含以下字段：

| 章节 | 标题 | 字数预估 | 核心场景 | POV | 情节进度 | 情感标签 |
|------|------|---------|---------|-----|---------|---------|
| 1 | [标题] | XXXX字 | [场景描述] | [主角] | 开端/建置 | 好奇、代入 |
| 2 | [标题] | XXXX字 | [场景描述] | [主角] | 开端/建置 | 悬念 |
| ... | ... | ... | ... | ... | ... | ... |

**字段说明**：
- **核心场景**：本章的主要场景和事件（1-2句话概括）
- **POV**：本章的叙事视角——多视角作品需明确每章视角。单视角作品统一为主角视角
- **情节进度**：本章在情节推进中的作用（引出冲突/深化矛盾/揭示信息/解决冲突/过渡衔接）
- **情感标签**：读者在本章应体验的主要情感（如：热血、悲伤、悬疑、温馨、震惊）

**章节标题命名规则**：
- 统一格式：`第N章 - <标题短语>`
- 标题建议 4-8 个汉字，提取本章核心意象或事件

#### 1.3 章节依赖关系

标注章节之间的依赖关系——某些章节必须在其他章节完成后方能生效：

- **信息依赖**：第M章揭示的信息是第N章情节的基础
- **状态依赖**：角色在第M章获得的能力/关系变化在第N章中使用
- **伏笔-回收依赖**：第M章的伏笔在第N章回收

### 第 2 步：人物弧线设计

从规格中提取人物设定，为每个主要角色设计完整的弧线（变化轨迹）：

#### 2.1 主要角色弧线表

| 角色 | 初始状态 | 触发事件 | 内在冲突 | 成长路径 | 最终状态 | 弧线类型 |
|------|---------|---------|---------|---------|---------|---------|
| [主角] | [开局状态] | [改变命运的触发] | [核心矛盾] | [如何克服/转变] | [结局状态] | 正向/负向/扁平 |
| [配角] | [开局状态] | [触发] | [矛盾] | [路径] | [结局] | 类型 |

**弧线类型**：
- **正向弧线**：角色克服弱点，成长为更好的版本
- **负向弧线**：角色因内心弱点或外部压力走向堕落或悲剧
- **扁平弧线**：角色本身不变，但改变周围世界或他人

#### 2.2 角色关系演进

设计角色关系的动态变化：

- **关系起点→终点**：每对核心关系的初始状态到最终状态的变化（如：敌对→同盟、疏离→亲密、崇拜→背叛）
- **关系转折点**：标注关系发生质变的章节位置
- **关系张力维护**：如何在前中期保持关系发展的悬念和张力

### 第 3 步：情节节奏规划

将整个故事的节奏可视化，确保读者体验的起伏有致：

#### 3.1 节奏曲线

使用文字描述或 ASCII 艺术绘制整体节奏曲线（横轴=章节，纵轴=紧张度/情感强度）：

```
紧张度 ▲
       │     ·  ·  ·     ··  ·  ← 高潮区 (J-K章)
       │    ·        ·  ·
       │   ·          ··       ← 转折区 (M-K章)
       │  ·                     
       │ ·                      
       │·                       ← 发展区 (N-M章)
       ·
       └──────────────────────────→ 章节
       开  发  转  高  结
       端  展  折  潮  局
```

#### 3.2 节奏控制策略

- **张弛比例**：紧张章节与舒缓章节的交替频率（如：每 2-3 章紧张情节后安排 1 章舒缓过渡/日常/情感戏）
- **信息密度控制**：确保每章有 1 个核心信息增量（新揭示/角色发展/情节推进），避免"水字数"
- **悬念节点规划**：标注每章结尾的悬念钩子类型（信息悬念/情感悬念/动作悬念）
- **高潮前的蓄势**：高潮章节前应有 3-5 章的铺垫蓄势，逐步拉升紧张度

#### 3.3 伏笔管理

- 列出所有规划的伏笔，标注埋设章节、回收章节、伏笔类型（信息伏笔/人物伏笔/情节伏笔）
- 确保所有伏笔在结局前有明确的回收规划
- 标注开放悬念（为系列作品预留的未解悬念）

### 第 4 步：生成设计文档

自动生成以下设计文档到 `specs/<NNN>-<name>/build/` 目录：

#### 4.1 人物关系图（`build/characters.md`）

- 使用 Mermaid 或文本图表绘制人物关系网络
- 标注关系类型（血缘/友情/爱情/敌对/利益/师徒）
- 标注关系动态变化的关键节点

#### 4.2 情节时间线（`build/timeline.md`）

- 按章节排列的完整事件时间线
- 每条事件包含：发生章节、事件描述、涉及角色、对主线的影响
- 标注并行发生的支线事件

#### 4.3 章节细纲（`build/outline.md`）

- 完整导出第 1 步生成的逐章细纲表
- 每章包含：标题、字数预估、核心场景、POV、情节进度、情感标签、悬念钩子
- 作为 implement 阶段的直接写作参考

#### 4.4 设定参考（`build/reference.md`）

- 世界设定核心规则汇总
- 角色设定速查表（每个角色的关键特征快速查询）
- 专有名词表（地名、特殊术语、物品名称等，确保全书统一）

### 第 5 步：宪法合规性检查

逐条对照宪法中的文学原则，确保计划中的设计决策符合宪法约束：

| 宪法原则 | 计划中的对应设计 | 合规性 | 备注 |
|---------|----------------|--------|------|
| [原则 1] | [计划中如何体现] | ✅/⚠️/❌ | [说明] |
| [原则 2] | [计划中如何体现] | ✅/⚠️/❌ | [说明] |
| ... | ... | ... | ... |

若发现合规性问题，在计划中标注 `[宪法违规：XXX]` 并提供替代方案。

### 第 6 步：写入计划文件

- 使用 `plugins/novel/templates/plan.md` 的结构
- 将步骤 1-5 的生成内容填充到模板中
- 写入 `specs/<NNN>-<name>/plan.md`
- 分别写入 4 个设计文档到 `specs/<NNN>-<name>/build/` 目录

## Output

- **主制品**：`specs/<NNN>-<name>/plan.md`
- **设计文档**：
  - `specs/<NNN>-<name>/build/characters.md` — 人物关系图
  - `specs/<NNN>-<name>/build/timeline.md` — 情节时间线
  - `specs/<NNN>-<name>/build/outline.md` — 章节细纲
  - `specs/<NNN>-<name>/build/reference.md` — 设定参考
- **格式**：Markdown，支持中文
- **内容类型**：`content_type: novel`

## Stage Checkpoints

- [ ] 章节拆分表完整，覆盖所有章节，每章有标题、字数、场景、POV
- [ ] 各阶段章节占比合理（开端 ~15%、发展 ~35%、转折 ~15%、高潮 ~20%、结局 ~15%）
- [ ] 人物弧线设计覆盖所有主要角色，有明确的初始状态→最终状态
- [ ] 节奏曲线有明确的张弛交替设计
- [ ] 所有伏笔有对应的回收规划
- [ ] build/ 目录下 4 个设计文档均已生成
- [ ] 宪法合规性检查无 ❌ 项（有问题的已标注并给替代方案）
- [ ] 规格中的每条 What/Why 在计划中都有对应的 How（可追溯）

## 质量门禁

- 章节拆分的总字数是否与规格中的内容规模估算一致（±15%）？
- 每个角色的弧线是否贯穿足够多的章节以显得自然（非"突然转变"）？
- 节奏规划中是否有足够的舒缓章节来避免读者疲劳？
- 伏笔列表中是否有遗漏的规格中暗示的情节线？
- 章节之间的信息依赖是否合理（无循环依赖）？
- 设计文档是否足够详细，使得 implement 阶段可以直接参考而无需回头查规格？

**下一步**：执行 `/specforge.tasks` 基于计划生成详细写作任务列表
