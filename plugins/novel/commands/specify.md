# 小说功能规格编写

## User Input

```text
$ARGUMENTS
```

根据用户输入创建 `specs/<NNN>-<feature>/spec.md` 小说规格文件。小说规格聚焦于 **WHAT**（写什么）和 **WHY**（为什么这样写），严格禁止涉及 **HOW**（怎么写——包括但不限于章节拆分、写作顺序、叙事技巧选择、分卷规划等）。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目（存在 `.specforge/` 目录）
2. 执行 `specforge list --detail --json` 确认当前活动 feature 和项目上下文
3. 执行 `specforge new "$ARGUMENTS" --dry-run --json` 预览将要创建的功能目录结构
4. 读取 `.specforge/constitution.md` 确保规格遵循宪法约束
5. 读取 `plugins/novel/templates/spec.md` 作为输出结构参考
6. 检查 `.specforge/feature.json` 确认功能目录名称（如已存在）

## Outline

### 第 1 步：创建功能目录

- 执行 `specforge new "$ARGUMENTS" --json` 创建 feature 分支和目录结构
- 解析命令输出获取 `FEATURE_DIR` 路径（格式：`specs/<NNN>-<name>/`）
- 确认 `specs/<NNN>-<name>/spec.md` 文件已初始化

### 第 2 步：解析用户输入 — 世界观设定

从 `$ARGUMENTS` 中提取世界观关键信息：

- **世界背景**：故事发生的时代、地域、社会结构、技术水平（如：架空古代修真世界、近未来赛博都市、二战背景欧洲）
- **核心规则**：这个世界的特殊规则或魔法体系（如：灵力体系、科技上限、超能力规则）
- **势力格局**：存在哪些主要势力（国家/宗门/组织），之间的核心矛盾是什么
- **信息差**：[NEEDS CLARIFICATION] 标注未明确的内容——例如："世界观中'灵气复苏'是渐进还是突变？社会反应如何？"

**重要**：若用户描述不足，基于题材提供合理的默认设定建议，标注为 `[建议]` 并提示用户确认。例如：
- 都市背景 → [NEEDS CLARIFICATION: 具体城市/国家？]
- 架空世界 → [建议] 创建世界地图和时间线

### 第 3 步：解析用户输入 — 内容规模

根据用户输入确定小说内容规模，使用以下维度：

- **总字数预估**：基于题材、故事框架和用户意图估算（如：30-50万字）
  - 若用户未提供，基于常识估算：长篇仙侠 100-300万字，都市言情 30-80万字，悬疑中篇 10-30万字
  - 标注 `[建议]` 并提示用户确认
- **目标章节数**：基于总字数预估和每章字数范围推算
  - 常见参考：网络文学章节 2000-4000字/章，传统出版 3000-5000字/章
- **每章字数范围**：如 2500-3500字/章
  - 根据发布平台惯例选择合理范围
- **完成度定义**：明确什么状态算"创作完成"——是全部章节完稿、还是定稿经过审核阶段

**输出格式**：

```markdown
| 维度 | 预估值 | 备注 |
|------|--------|------|
| 总字数 | XXX万字 | [建议/用户指定] |
| 目标章节数 | XX章 | 基于每章XXX字推算 |
| 每章字数 | XXXX-XXXX字 | [平台习惯/创作节奏] |
| 创作周期 | X个月 | [估算依据] |
```

### 第 4 步：解析用户输入 — 人物设定目标

从用户输入中提取人物信息，整理为角色设定表：

| 角色 | 身份 | 性格 | 核心动机 | 与其他角色关系 |
|------|------|------|----------|----------------|
| [主角名] | [身份/职业] | [3-5个关键词] | [一句话动机] | [与XX的关系] |
| [配角1] | [身份/职业] | [3-5个关键词] | [一句话动机] | [与XX的关系] |
| ... | ... | ... | ... | ... |

**人物类型覆盖检查**：
- 至少 1 个主角（protagonist）—— 故事的核心代理，读者通过其视角体验故事
- 至少 1 个核心配角（deuteragonist）—— 对主角有重要影响的角色
- 至少 1 个对手/反派（antagonist）—— 不一定邪恶，但与主角目标存在冲突
- 可选：导师角色、搞笑担当、悲剧角色等

若用户未提供人物信息，使用 `questionary` 交互式询问：
1. "主角的姓名和身份是什么？"
2. "请用 3-5 个关键词描述主角的性格"
3. "主角的核心动机是什么？（Ta 最想要什么？）"
4. "(可选) 是否有重要的配角或反派需要定义？"

### 第 5 步：解析用户输入 — 情节大纲（5 阶段）

根据用户输入构建情节大纲，使用 5 阶段结构（开端→发展→转折→高潮→结局）：

1. **开端（建置）**：介绍世界、主要角色和初始状态，暗示核心冲突
   - 关键产出：读者在开篇后应能回答"这是谁的故事？发生在什么世界？"
2. **发展（上升行动）**：冲突升级，角色成长，支线展开
   - 关键产出：主要冲突已确立，角色已踏上旅程
3. **转折（中点/危机）**：故事方向改变，重大揭示或失败
   - 关键产出：故事不可逆转地改变方向，风险升级
4. **高潮（对决）**：核心冲突的最终对决
   - 关键产出：主要冲突得到解决或面临终极考验
5. **结局（收束）**：各条线的收束，最终状态呈现
   - 关键产出：读者明确知道故事的最终结果

每个阶段应包含：
- **阶段目标**：本阶段在整体叙事中的作用（1-2句）
- **核心事件**：本阶段发生的关键事件（3-5 个）
- **情感曲线**：读者在本阶段应有的情感体验（如：悬念→紧张→惊讶）

**重要约束**：
- **禁止**在每个阶段中指定具体章节编号或章节拆分方案
- **禁止**规定写作顺序（如"先写第3章再写第1章"）
- **禁止**指定叙事技巧（如"使用倒叙手法"、"采用多视角叙述"）——叙事技巧属于 HOW 层
- 仅描述"发生了什么"和"为什么这样发展"（WHAT + WHY）

### 第 6 步：定义读者旅程（Reader Journey）

读者旅程描述目标读者阅读小说的体验路径，使用 Given-When-Then 格式（最少 2 个旅程）：

#### 读者旅程 1 — [旅程标题] (Priority: P1)

描述读者从开篇到第一个情感高潮的完整体验

**Why this priority**：此旅程定义读者是否会被作品吸引并继续阅读（留存率的核心驱动力）

**Independent Test**：可以通过向测试读者提供开篇章节并收集阅读感受来独立验证

**Acceptance Scenarios**：

1. **Given** 读者开始阅读第一章，**When** 读完第一节，**Then** 读者能清晰认知主角的身份和故事世界的基本设定
2. **Given** 读者完成开篇阅读，**When** 到达章节结尾，**Then** 读者有强烈的"想知道接下来发生什么"的欲望
3. **Given** 读者是目标受众群体的一员，**When** 完成前三章阅读，**Then** 读者能准确描述故事的核心冲突和情感钩子

---

#### 读者旅程 2 — [旅程标题] (Priority: P2)

描述读者经历完整故事弧线的体验

**Why this priority**：此旅程定义作品的核心价值是否被读者完全接收（作品完整性的体现）

**Independent Test**：可以通过让读者阅读完整故事大纲/样章并提供反馈来独立验证

**Acceptance Scenarios**：

1. **Given** 读者已阅读完整故事，**When** 回顾主要角色的成长轨迹，**Then** 读者能清晰描述每个主要角色的变化弧线
2. **Given** 读者阅读到故事中期转折点，**When** 转折事件发生，**Then** 读者产生预期的情感反应（如震惊、悲伤、愤怒）

---

#### 读者旅程 3 — [旅程标题] (Priority: P3)（可选）

可根据需要添加第 3 个旅程，例如：特定角色的视角体验、副线剧情的沉浸等

### 第 7 步：定义成功标准

定义衡量小说创作是否成功的标准，必须是可衡量、可验证的：

1. **SC-001 完整性**：所有规划的情节线均已闭合，无未解决的悬念（除非为系列作品预留）
2. **SC-002 角色弧线完成度**：每个主要角色从初始状态到最终状态的变化可在回顾中清晰追踪
3. **SC-003 字数达标**：完成稿的字数落在规划的目标范围内（±15% 容差）
4. **SC-004 读者测试**：目标读者测试中，80% 的读者能准确复述故事的核心冲突和结局
5. **SC-005 情感共鸣**：读者在关键情感节点的感受反馈与设计意图匹配度 > 70%

### 第 8 步：记录假设和边界

- 列出在规格中做出的关键假设（需用户确认的内容）：
  - `[假设]` 目标读者群：XXX
  - `[假设]` 发布平台和格式：XXX（如网文连载 / 一次出版）
  - `[假设]` 系列作品规划：XXX（如"独立作品"、"三部曲第一部"）
- 列出明确的**不在此作品范围内**的内容：
  - 例如："本作品不包含前传/外传内容"、"不涉及平行宇宙设定"

### 第 9 步：写入规格文件

- 使用 `plugins/novel/templates/spec.md` 的结构
- 将步骤 2-8 的生成内容填充到模板中
- 写入 `specs/<NNN>-<name>/spec.md`
- 确保所有 `[NEEDS CLARIFICATION]` 标记已正确生成，供后续 `/specforge.clarify` 处理

## Output

- **制品**：`specs/<NNN>-<name>/spec.md`
- **格式**：Markdown，支持中文
- **位置**：`specs/<NNN>-<name>/spec.md`
- **内容类型**：`content_type: novel`

## Stage Checkpoints

- [ ] 功能目录已通过 `specforge new` 创建成功
- [ ] 世界观设定包含背景、核心规则、势力格局三大要素
- [ ] 内容规模表已填写完整，含总字数/章节数/每章字数
- [ ] 人物设定表至少包含 1 个主角、1 个核心配角、1 个对手/反派
- [ ] 情节大纲覆盖 5 个阶段，每个阶段有阶段目标、核心事件、情感曲线
- [ ] 读者旅程至少 2 个，每个含 Why Priority、Independent Test、Given-When-Then
- [ ] 成功标准至少 3 条，每条可衡量
- [ ] 规格中**无**章节编号、写作顺序、叙事技巧等 HOW 层内容
- [ ] 所有 [NEEDS CLARIFICATION] 标记准确反映信息缺失点
- [ ] [建议] 标记已标注为待用户确认

## 质量门禁

- 规格是否符合"只描述 WHAT 和 WHY"的约束？（逐条检查是否有 HOW 内容混入）
- 读者旅程中的 Given-When-Then 是否具体到可以独立验证？
- 内容规模估算是否有合理依据（非凭空捏造）？
- 人物设定表中的每个角色是否有明确的动机和关系？
- 5 个情节阶段之间是否有清晰的因果关系（非简单的"然后...然后..."并列）？
- 宪法中的文学原则是否在本规格中得到遵循？（逐条对照检查）

**下一步**：若存在 [NEEDS CLARIFICATION] 标记 → 执行 `/specforge.clarify`；否则 → 执行 `/specforge.plan`
