# 小说创作宪法管理

## User Input

```text
$ARGUMENTS
```

根据用户输入创建或修改 `.specforge/constitution.md` 宪法文件。小说宪法是 SpecForge SDD 工作流的文学基石，定义了作品的核心文学原则、叙事质量标准和创作治理规则。所有后续阶段（specify、plan、implement、review）的命令在执行时必须遵循宪法约束。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目（存在 `.specforge/` 目录）
2. 执行 `specforge list --detail --json` 确认当前活动 feature 和项目上下文
3. 读取 `plugins/novel/templates/constitution.md` 作为输出结构参考
4. 若 `.specforge/constitution.md` 已存在，视为更新操作——保留已有原则，仅根据用户输入调整或补充
5. 检查用户输入是否提供了足够的小说创作方向信息（如题材、基调、目标读者）

## Outline

### 第 1 步：解析用户输入

- 从 `$ARGUMENTS` 中提取关键信息：
  - **小说题材**：玄幻、科幻、言情、悬疑、历史、都市、武侠、末世等
  - **叙事基调**：严肃深沉、轻松幽默、热血激昂、温情治愈、黑暗压抑等
  - **目标读者**：年龄段、阅读偏好、文化背景
  - **核心创作理念**：用户明确提出的不可妥协的文学追求或限制
  - **篇幅规划**：长篇（100万字+）、中长篇（30-100万字）、中篇（5-30万字）、短篇（<5万字）
- 若用户输入为空或信息不足，使用 `questionary` 交互式询问关键缺失项：
  1. "请选择小说题材" → 选项列表
  2. "请描述叙事基调" → 自由文本
  3. "目标读者是谁？" → 选项或自由文本
  4. "是否有不可妥协的创作原则？" → 自由文本（可选）
- 从用户输入中识别可能的内容类型特有约束：例如"硬科幻"→ 科学准确性原则，"言情"→ 情感逻辑自洽原则

### 第 2 步：加载宪法模板

- 读取 `plugins/novel/templates/constitution.md` 获取小说宪法结构
- 模板包含以下章节：
  - `# [作品名称] 创作宪法`
  - `## 文学原则`（含 `### [原则名称]`、描述和 `**理由**`）
  - `## 叙事标准`（含 `NS-###` 编号的质量标准）
  - `## 治理规则`（修订流程和版本管理）

### 第 3 步：定义文学原则（最少 3 条，推荐 5 条）

引导用户定义 3-5 条核心文学原则。建议按以下维度覆盖（至少覆盖前 3 条）：

1. **叙事逻辑原则**（最重要）：情节发展的因果链条必须合理吗？角色行为必须有动机吗？
   - 例如："情节推动必须由角色决策驱动，禁止依赖巧合作为关键情节转折"
   - 例如："所有角色行为必须有可追溯的心理动机，禁止角色为剧情服务而违背其性格"
2. **风格与语言原则**：作品的语言风格和叙事视角有何约束？
   - 例如："叙事语言必须保持第三视角客观叙述，禁止直接说教或道德评判"
   - 例如："对话语言必须符合角色身份和时代背景"
3. **角色塑造原则**：角色设计的质量底线在哪里？
   - 例如："主要角色必须有完整的背景故事，禁止出现'扁平工具人'"
   - 例如："女性角色必须拥有独立人格和主动行为动机，禁止沦为男性角色的附属品"
4. **世界观一致性原则**（可选但推荐）：架空世界或历史背景的内部逻辑必须自洽
   - 例如："世界观设定的所有规则必须保持前后一致，新增设定不得与已有设定矛盾"
5. **读者体验原则**（可选）：对读者的承诺
   - 例如："每章结尾必须有情感余韵或悬念钩子，确保读者有继续阅读的欲望"

每条文学原则包含三个部分：
- **原则名称**：简短摘要（1 句话），格式为 `第X条 — <原则名>`
- **描述**：具体说明（3-5 句），定义本原则的适用范围和判断标准。应包含正面指导 + 反面禁止，使原则具有可操作性
- **理由**：说明为什么这条原则对小說的文学质量至关重要

若用户未明确提供足够信息，基于题材和基调提供合理默认值，并在每条原则后标注 `**[建议原则——请审查确认]**`。

### 第 4 步：定义叙事标准

列出适用于所有 SDD 阶段制品的小说叙事质量检查维度，使用 NS-### 编号：

通用叙事标准：

- **NS-001 情节完整性**：所有情节线均已规划闭合路径，无弃坑风险标记
- **NS-002 角色一致性**：角色行为、语言风格、心理动机在全文中保持一致，角色弧线有明确起止状态
- **NS-003 世界观自洽性**：架空设定规则无内部矛盾，新增设定与已有设定兼容
- **NS-004 叙事清晰性**：时间线、空间转换、视角切换明确无误，无歧义标记

题材特有标准（根据题材自动选择或提示用户选择）：

| 题材 | 特有标准 |
|------|---------|
| 玄幻 | NS-005 修炼体系一致性：等级设定、晋升路径、能力边界保持统一 |
| 科幻 | NS-005 科学可解释性：科学技术设定有合理推演路径，非"魔法式"解决 |
| 言情 | NS-005 情感逻辑自洽性：感情发展有合理递进，转折有铺垫 |
| 悬疑 | NS-005 伏笔回收完整性：所有埋设的线索均有对应揭示或解释 |
| 历史 | NS-005 历史考据准确性：时代背景、礼仪服制、社会制度与设定朝代一致 |
| 都市/现代 | NS-005 现实逻辑合理性：现代场景描写符合常识，无明显专业错误 |
| 武侠 | NS-005 武学体系自洽性：武功等级、内功体系、门派关系前后一致 |
| 末世 | NS-005 生存逻辑合理性：资源分配、社会秩序崩溃过程有合理推演 |

### 第 5 步：设定治理规则

定义小说宪法的修订流程和版本管理：

**修订流程**：
1. **提议**：任何创作参与者可提交修订提案，说明修改动机和影响范围（需明确影响哪些已有章节）
2. **审查**：维护者（主编/主笔）评估合理性和对已有内容的影响
3. **批准**：审查通过后合并修订
4. **传播**：同步更新依赖制品的宪法引用，标记受影响的章节是否需要修改

**版本管理**：使用 MAJOR.MINOR.PATCH 语义版本
- **MAJOR**：移除或重新定义核心文学原则，可能推翻已有章节内容
- **MINOR**：新增原则、叙事标准或扩展现有原则的适用范围
- **PATCH**：措辞澄清、示例补充、错别字修正

### 第 6 步：写入宪法文件

- 使用模板结构，用第 3-5 步的生成内容填充占位符
- 写入 `.specforge/constitution.md`
- 确保版本号设为 `1.0.0`，批准日期和最后修订日期为当前日期
- 若为更新操作：保留当前版本号，根据变更幅度递增版本
- 在文件末尾添加 `**宪法版本**: x.y.z | **批准日期**: YYYY-MM-DD | **最后修订**: YYYY-MM-DD`

## Output

- **制品**：`.specforge/constitution.md`
- **格式**：Markdown，支持中文
- **位置**：项目根目录 `.specforge/constitution.md`
- **内容类型标识**：文档头部包含 `content_type: novel` 元数据

## Stage Checkpoints

- [ ] 至少定义 3 条文学原则，每条有名称、描述和理由
- [ ] 文学作品原则包含正面指导 + 反面禁止，具有可操作性
- [ ] 叙事标准至少涵盖完整性、一致性、自洽性、清晰性四类
- [ ] 根据题材选择了至少 1 条题材特有叙事标准
- [ ] 版本号和日期已填写
- [ ] 宪法内容与小说创作类型对齐
- [ ] 无模糊占位符残留（如 `[PROJECT_NAME]`、`[PRINCIPLE_1_NAME]` 等）
- [ ] 若用户输入提供了明确创作理念，所有原则均已体现

## 质量门禁

- 文学原则是否具体到可以判断具体章节是否违规？
- 叙事标准是否涵盖从规格到实施的完整质量检查维度？
- 题材特有标准是否与项目实际题材匹配？（不匹配的题材标准不应包含）
- 治理规则是否包含修订流程和版本管理？
- 是否明确了约束对已有内容的影响范围评估机制？

**下一步**：执行 `/specforge.specify` 基于本宪法创建小说规格说明
