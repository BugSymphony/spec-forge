# 小说逐章写作实施

## User Input

```text
$ARGUMENTS
```

根据实施计划（`specs/<NNN>-<name>/plan.md`）和章节细纲（`specs/<NNN>-<name>/build/outline.md`）逐章执行小说写作。每章输出为独立的 Markdown 文件，存放于 `dist/novel/` 目录。支持断点续写、指定章节重写和批量生成。

## Pre-Execution Checks

1. 确认当前活动 feature 目录存在（`specs/<NNN>-<name>/`）
2. 执行 `specforge list --detail --json` 确认当前状态
3. 读取 `specs/<NNN>-<name>/plan.md` 确认章节拆分和人物弧线设计
4. 读取 `specs/<NNN>-<name>/build/outline.md` 获取当前目标章节的细纲
5. 读取 `specs/<NNN>-<name>/build/reference.md` 加载设定参考（人物特征、专有名词）
6. 读取 `specs/<NNN>-<name>/build/characters.md` 确认本章涉及角色的弧线进度
7. 读取 `.specforge/constitution.md` 确保写作遵循文学原则
8. 检查 `dist/novel/` 目录是否存在，不存在则创建
9. 扫描 `dist/novel/` 已有章节，确定待写作的目标章节：
   - 若 `$ARGUMENTS` 指定了章节（如"第5章"），以该章为目标
   - 若 `$ARGUMENTS` 为空，以"已完成的最后一章 + 1"为目标
   - 若 `$ARGUMENTS` 包含"重写"关键词，覆盖已有章节文件

## Outline

### 第 1 步：确定写作目标

- 解析 `$ARGUMENTS` 确定写作模式：
  - **续写模式**（默认）：自动检测 `dist/novel/` 下最大章节编号 N，目标为第 N+1 章
  - **指定章节模式**：`$ARGUMENTS` 包含章节号（如"第5章"、"chapter 3"），以该章为目标
  - **重写模式**：`$ARGUMENTS` 包含"重写"+"章节号"，覆盖已有章节
  - **批量模式**：`$ARGUMENTS` 包含范围（如"第3-5章"），依次写作多章
- 确认目标章节的细纲信息（标题、字数预估、核心场景、POV、情节进度、情感标签、悬念钩子）
- 若目标章节不存在于细纲中，ERROR：提示章节编号超出计划范围

### 第 2 步：加载上下文

在开始写作前，加载必要的上下文信息：

#### 2.1 前情回顾

- 若目标章节为第 N 章（N > 1），读取 `dist/novel/第N-1章-*.md` 获取最近一章的结尾状态
- 提取关键上下文变量：
  - **场景位置**：上一章结尾的角色位置/场景
  - **角色状态**：关键角色的当前情绪、身体状况、所处情境
  - **未解决事件**：上一章结尾遗留的即时冲突或悬念
  - **时间线**：当前故事时间点
- 若目标章节为第 1 章，从规格中提取世界观初始状态

#### 2.2 角色状态快照

- 从 `build/characters.md` 中提取本章涉及角色的弧线进度
- 确认每个角色在本章中的"当前状态"和"本章应在弧线中前进的步骤"
- 构建角色速查卡：

```text
[角色名]
├── 当前情绪: XXX
├── 当前位置: XXX
├── 本章动机: XXX
├── 本章弧线目标: XXX（角色在本章应展现的变化或揭示）
└── 语言风格: XXX（口癖、句式偏好、正式度）
```

#### 2.3 设定速查

- 加载本章涉及的世界设定规则、专有名词、地点描述
- 确保描述与已有章节一致

### 第 3 步：章节写作

按照细纲和上下文信息执行写作。写作遵循以下结构：

#### 3.1 章节元数据

每章文件开头包含 YAML frontmatter：

```yaml
---
chapter: N
title: "章节标题"
word_count_target: XXXX
word_count_actual: XXXX
pov: "角色名"
emotion_tags: ["标签1", "标签2"]
status: draft
created: YYYY-MM-DD
revised: YYYY-MM-DD
---
```

#### 3.2 正文写作规范

- **开篇钩子**：第 1 段必须有足够的吸引力——可以是悬念、冲突暗示、反常现象或强烈情感
- **场景构建**：每章应有 1-3 个主要场景，场景切换使用 `---` 分割线
- **对话比例**：对话占比建议 30-50%，避免连续长段叙述
- **描写节奏**：动作场景短句快节奏，情感场景长句慢节奏，日常场景中等节奏
- **结尾钩子**：每章倒数 2-3 段设置悬念钩子（信息悬念/情感悬念/动作悬念），确保读者有继续阅读的动力

#### 3.3 叙事质量自检

写作过程中实时检查以下维度：

- [ ] **宪法原则合规**：本段/本章是否符合宪法中的文学原则？（逐条对照）
- [ ] **角色一致性**：角色的对话风格、行为逻辑、心理反应是否符合其在规格中的设定？
- [ ] **世界观自洽**：场景描述是否与世界观设定一致？（如有魔法体系→使用规则正确，历史背景→时代细节准确）
- [ ] **前情连贯**：本段内容是否与前文章节衔接自然？（时间/空间/状态连续性）
- [ ] **信息增量**：本章至少为读者提供了 1 个新的重要信息（角色密码/世界观规则/情节推进）
- [ ] **情感标签匹配**：已完成段落的整体情感基调是否与细纲中的情感标签一致？

#### 3.4 字数控制

- 写作过程中跟踪统计字数（中文字符数）
- 当达到目标字数的 80% 时发出提示
- 目标字数 ±15% 为合格范围
- 超出上界时，检查是否有冗余描写或无关对话
- 不足下界时，检查场景是否过于简略、是否有可深化的情感描写

### 第 4 步：章节后处理

#### 4.1 质量审查标记

在章节末尾添加质量审查标记区域：

```markdown
<!-- REVIEW_MARKS
角色[X]在本章的表现：符合其弧线设计 / 需要检查
情节进度：与计划一致 / 有偏差需要回溯
情感标签匹配：✅ / ⚠️ / ❌
字数：实际XXX字（目标XXX字，偏差±X%）
伏笔埋设：本章新增 X 个、回收 X 个
宪法合规：全部通过 / 需关注第X条
-->
```

#### 4.2 更新字数统计

- 将实际字数写入 frontmatter 的 `word_count_actual` 字段
- 更新 `status` 字段：`draft` → 等待 review, `reviewed` → 已审查通过

#### 4.3 更新进度追踪

在 `dist/novel/progress.md` 中更新写作进度：

```markdown
| 章节 | 标题 | 状态 | 字数 | 完成日期 | 审查状态 |
|------|------|------|------|---------|---------|
| 1 | [标题] | reviewed | 3200 | 2025-06-01 | ✅ |
| 2 | [标题] | draft | 2800 | 2025-06-02 | 待审查 |
| ... | ... | ... | ... | ... | ... |
| **总计** | | | XXXX / XXXX(目标) | | |
```

### 第 5 步：输出章节文件

- 将完成章节写入 `dist/novel/第N章-<标题>.md`
- 文件命名格式：`第N章-<标题>.md`（N 为章节编号，标题使用细纲中的标题）
- 确保文件编码为 UTF-8

## Output

- **制品**：`dist/novel/第N章-<标题>.md`
- **格式**：Markdown（含 YAML frontmatter），支持中文
- **位置**：`dist/novel/`
- **进度追踪**：`dist/novel/progress.md`（自动更新）

## Stage Checkpoints

- [ ] 目标章节编号已确认，细纲信息已加载
- [ ] 前情回顾完成，上下文变量已提取
- [ ] 角色状态快照已构建（本章涉及的所有角色）
- [ ] 章节 frontmatter 完整（章节号、标题、字数目标、POV、情感标签）
- [ ] 开篇钩子和结尾钩子均已设置
- [ ] 叙事质量自检清单 6 项均已检查通过
- [ ] 字数在目标范围 ±15% 内
- [ ] 质量审查标记已填写
- [ ] 进度追踪文件已更新

## 质量门禁

- 本章是否可以作为独立片段阅读？（即使脱离前后文，读者能否理解基本场景和人物？）
- 角色的对话是否各有特色？（不同角色应有可区分的语言风格）
- 是否有"为剧情服务"强行改变角色行为的段落？
- 场景描写是否充分调动了感官（视觉 + 至少 1 种其他感官：听觉/嗅觉/触觉/味觉）？
- 本章是否推进了至少 1 条情节线或角色弧线？
- 是否避免了信息倾泻？（世界观和背景信息应融入叙事，非大段说明性文字）
