# 写作任务: [作品名称]

**输入**: 设计文档 `specs/<NNN>-<name>/`

**前置条件**: plan.md（必需）、spec.md（必需）、build/outline.md（必需）

**组织方式**: 任务按阶段组织，每章为一个任务单元。任务标注 [P] 表示可并行（不同章节，无依赖冲突）。

## 格式说明

- **[P]**：可并行执行（不同章节，无依赖关系）
- **[Chapter N]**：对应第 N 章的写作任务
- **[Review]**：审查类任务
- **[Design]**：设计文档生成任务

## 路径约定

- 输出目录：`dist/novel/`
- 文件命名：`第N章-<标题>.md`
- 进度追踪：`dist/novel/progress.md`
- 设计文档：`specs/<NNN>-<name>/build/`

## 依赖与执行顺序

### 阶段依赖

- **初始化 (Phase 1)**：无依赖——可立即开始
- **设计文档 (Phase 2)**：依赖 Phase 1 —— 需要目录结构就绪
- **开端写作 (Phase 3)**：依赖 Phase 2 —— 需要设计文档参考
- **发展阶段 (Phase 4)**：依赖 Phase 3 —— 需要建立开端状态
- **转折阶段 (Phase 5)**：依赖 Phase 4 —— 需要发展阶段的积累
- **高潮阶段 (Phase 6)**：依赖 Phase 5 —— 需要转折后的新方向
- **结局阶段 (Phase 7)**：依赖 Phase 6 —— 需要对决结果
- **审查打磨 (Phase 8)**：依赖 Phase 3-7 —— 全部章节完成

### 章内依赖关系

<!-- 根据 plan.md 的章节依赖关系表填充 -->

- **第X章 → 第Y章**：[依赖类型：信息依赖/状态依赖/伏笔回收]
- 无依赖标记的章节可在相邻章节完成后顺序推进

### 并行机会

- 所有 [P] 标记的任务可并行执行
- Phase 2 所有设计文档生成任务可并行
- Phase 8 中：情节审查、角色审查、语言审查三门可并行
- 不同章节的写作任务不可并行（需保持前后文连贯）

## 实施策略

### 逐章推进策略（推荐单人创作）

1. 完成 Phase 1 + Phase 2 → 基础就绪
2. Phase 3-7：从第1章到最终章，顺序写作
   - 每完成一章即更新 progress.md
   - 每完成一个阶段执行 phase checkpoint 验证
3. Phase 8：全部章节完成后统一审查

### 分批审查策略

1. 每完成一个阶段（Phase 3/4/5/6/7），即对该阶段进行阶段内审查
2. 所有阶段完成后进行跨阶段综合审查（Phase 8）
3. 优点：早发现问题早修复，减少大规模返工

## 备注

- [P] 任务 = 不同文件，无依赖冲突
- [Chapter N] 标签映射到具体章节，可追溯
- 每章写作参考 `build/outline.md` 中对应章节的细纲
- chapter frontmatter 中的 status 字段追踪完成状态：draft → reviewed
- 每章完成后更新 `dist/novel/progress.md`
- 每完成一个阶段执行 checkpoint 验证，确认阶段目标达成
