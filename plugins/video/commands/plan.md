# 短剧创作计划

## User Input

```text
$ARGUMENTS
```

根据 spec.md 中定义的短剧创作目标，生成详细的"怎么做"方案。plan 阶段仅关注 **HOW**（场次如何设计、镜头如何组织、时长如何分配、转场如何衔接），严格禁止在本阶段重新定义或修改 WHAT/WHY 层面的内容（那属于 specify 阶段）。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目（存在 `.specforge/` 目录）
2. 执行 `specforge list --detail --json` 确认当前活动 feature
3. 执行 `specforge validate --stage specify --json` 确认 spec.md 已通过校验
4. 若校验失败，ERROR：提示先完成 specify 阶段后再执行 plan
5. 执行 `specforge setup plan --json` 初始化 plan 环境（复制模板、创建 build/ 目录）
6. 读取 `.specforge/constitution.md` 确认宪法约束（特别是制作标准和节奏准则）
7. 读取 `{feature_dir}/spec.md` 获取创作目标和场次目标

## Outline

### 第 1 步：解析 spec.md 的 WHAT/WHY

从 spec.md 中提取以下信息作为 plan 的输入：
- 故事梗概 → 用于拆解为具体场次
- 风格方向 → 用于确定镜头语言风格和转场风格
- 内容规模（总集数、每集时长、总时长）→ 用于时长分配计算
- 场次目标（含 Priority）→ 用于确定场次设计优先级
- 核心要素（冲突、情感主线、节奏曲线）→ 用于指导分场节奏

### 第 2 步：设计分场结构

基于故事梗概和场次目标，设计完整的分场结构表。每集包含以下要素：

```markdown
| 集数 | 场次标题 | 剧情目标 | 情感目标 | 场景位置 | 出场角色 | 预估时长（秒）|
|------|---------|---------|---------|---------|---------|-------------|
| 01   | [标题]   | [该场次要推动的剧情] | [观众应产生的情感] | [场景] | [角色列表] | [秒数] |
```

**设计约束**：
- 每集时长之和必须等于 spec 中定义的每集时长（±5 秒容差）
- 总集数必须等于 spec 中定义的总集数
- 每集必须包含：开场 hook（0-5 秒）+ 剧情推进（主体）+ 结尾落点（最后 5-10 秒）
- 情感曲线必须与 spec 中定义的节奏曲线一致

**节奏设计规则**：
- 开场 hook：前 3-5 秒必须有强吸引力元素（冲突/悬念/情感爆发/意外反转）
- 主体叙事：信息密度逐渐提升，对白与留白交替
- 结尾落点：必须有悬念钩子或情感收束，驱动观众继续观看下一集

### 第 3 步：编写镜头列表

为每个场次设计详细的镜头序列。镜头列表格式：

```markdown
### 第 N 集：[场次标题]

| 镜号 | 景别 | 画面描述 | 动作/调度 | 对白/旁白概要 | 预估时长（秒）|
|------|------|---------|----------|-------------|-------------|
| N01  | [景别] | [画面内容] | [演员动作/相机运动] | [对白摘要] | [秒] |
| N02  | [景别] | [画面内容] | [演员动作/相机运动] | [对白摘要] | [秒] |
```

**景别规范**：
- 远景（EST）：建立场景空间关系
- 全景（LS）：展示人物全身和场景关系
- 中景（MS）：展示人物上半身动作和互动（最常用景别）
- 近景（MCU）：展示人物面部表情和情绪
- 特写（CU）：强调关键物品、表情细节、动作细节
- 大特写（ECU）：极端强调（慎用，全剧不超过 3 次）

**镜头设计原则**（遵循宪法）：
- 特写镜头占比不低于 30%
- 连续镜头间禁止跳轴（视线方向/运动方向必须一致）
- 同一场景内的景别变化必须平滑（如 LS → MS → MCU → CU，禁止 LS → ECU 突然跳变）
- 对白镜头与反应镜头交替，避免长时间单一景别

### 第 4 步：时长分配计算

根据 spec 中定义的单集时长，为每集每个镜头精确分配时长：

1. **从总体到单集**：
   - 总时长 / 总集数 = 每集目标时长（秒）
   - 每集目标时长自动拆分为：hook 段 + 主体段 + 结尾段

2. **单集内部分配检查**：
   - hook 段时长：3-5 秒（占 3-6%）
   - 主体段时长：每集目标时长 − hook 段 − 结尾段
   - 结尾段时长：5-10 秒（占 8-12%）

3. **每集镜头时长累加校验**：
   - 所有镜头时长之和 = 每集目标时长（±5 秒容差）
   - 若超出容差，调整镜头数或单镜头时长

4. **全剧时长校验**：
   - 所有集数时长之和 = 总时长目标（±10 秒容差）

### 第 5 步：转场规划

设计集间转场和集内转场策略：

**集内转场**（镜头间的过渡方式）：
- **硬切（Cut）**：直接切换，适合快节奏对话和动作场景
- **淡入淡出（Fade）**：用于时间流逝或场景大跨度切换
- **叠化（Dissolve）**：用于情绪过渡或回忆闪回
- **划像（Wipe）**：用于场景转换或风格化过渡

**集间衔接**（上一集结尾 → 下一集开场的过渡）：
- 上一集结尾定格在关键情感表情或悬念元素上
- 下一集开场 2 秒内回扣上一集结尾的情绪/信息
- 若为独立单集（无前后关联），结尾为情感收束，非悬念

**转场设计表**：

```markdown
| 集数 | 结尾镜头 | 结尾情绪 | 转场方式 | 下集开场镜头 | 衔接逻辑 |
|------|---------|---------|---------|------------|---------|
| 01   | [描述]   | [情绪]   | [方式]   | [描述]      | [如何衔接] |
```

### 第 6 步：生成设计文档

在 `{feature_dir}/build/` 下生成短剧类型专用的设计文档：

#### 6a. 分镜头脚本模板（`build/分镜头脚本模板.md`）

生成标准化的分镜头脚本编写模板，供 implement 阶段使用：

```markdown
# 分镜头脚本模板

## 基本信息
- 剧集：[第N集]
- 场次标题：[标题]
- 编剧：[姓名]
- 日期：[DATE]

## 镜头列表
| 镜号 | 景别 | 时长(s) | 画面描述 | 动作调度 | 对白/旁白 | 音效/音乐 | 备注 |
|------|------|--------|---------|---------|---------|----------|------|
```

此模板含完整的字段定义和填写说明，确保 implement 阶段的输出格式统一。

#### 6b. 场景布置方案（`build/场景布置方案.md`）

为每个主要场景生成布置方案：

```markdown
# 场景布置方案

## 场景概览
| 场景编号 | 场景名称 | 出现集数 | 场景类型 | 基础色调 |
|---------|---------|---------|---------|---------|
| S01     | [名称]   | [集数范围] | 内景/外景 | [色调] |

## 场景 S01 详细布置
- **空间描述**：[空间的大小、形状、结构]
- **主要道具**：[道具清单，含位置描述]
- **灯光方案**：[主光源方向、色温、氛围]
- **色彩基调**：[墙面/家具/装饰的主色和辅色]
- **特殊要求**：[如绿幕区域、运动镜头空间预留等]
```

#### 6c. 演员道具清单（`build/演员道具清单.md`）

```markdown
# 演员道具清单

## 角色造型
| 角色 | 集数 | 服装套数 | 发型 | 妆容风格 | 特殊造型要求 |
|------|------|---------|------|---------|------------|
| [角色] | [集数] | [数量]  | [发型] | [妆容]  | [如伤妆/老年妆] |

## 道具清单
| 道具编号 | 道具名称 | 出现集数 | 类型 | 数量 | 备注 |
|---------|---------|---------|------|------|------|
| P001    | [名称]   | [集数]   | 手持/陈设 | [数量] | [特殊要求] |
```

### 第 7 步：生成通用设计文档

与类型专用文档并行生成通用框架文档：

- `build/research.md`：短剧创作的技术参考和市场分析
- `build/quickstart.md`：新成员快速上手的脚本编写指南
- `build/contracts/`：脚本格式合约和各集接口约定

### 第 8 步：宪法合规检查

对照短剧宪法逐项检查 plan 内容：

- [ ] 每集是否有明确的情感 hook（前 3-5 秒抓住注意力）？
- [ ] 每集结尾是否有悬念或情感落点？
- [ ] 特写镜头占比是否 ≥ 30%？
- [ ] 镜头序列中是否无跳轴错误（检查相邻镜头的视线方向和运动方向）？
- [ ] 每集时长是否在目标时长 ±5 秒内？
- [ ] 景别变化是否平滑（无越级跳变）？
- [ ] 台词概要是否通过口语化朗读测试标准？
- [ ] 对白与留白比例是否接近 6:4？

若存在宪法违反项，在 plan.md 的「宪法合规检查」章节记录偏差和理由。

### 第 9 步：写入创作计划文件

1. 定位 feature 目录：使用 `specforge show --paths-only` 获取路径
2. 读取 `.specforge/templates/plan-template.md` 获取短剧 plan 模板
3. 用第 2-8 步生成的内容填充模板各章节
4. 写入 `{feature_dir}/plan.md`
5. 执行 `specforge validate --stage plan --json` 校验计划完整性
6. 若校验失败，根据错误信息修正后重新写入

## Output

- **制品**：`{feature_dir}/plan.md`
- **设计文档**（写入 `{feature_dir}/build/`）：
  - `build/research.md` — 技术参考和市场分析
  - `build/quickstart.md` — 脚本编写快速指南
  - `build/contracts/` — 脚本格式合约
  - `build/分镜头脚本模板.md` — 标准化分镜脚本编写模板
  - `build/场景布置方案.md` — 各场景详细布置方案
  - `build/演员道具清单.md` — 角色造型和道具清单
- **格式**：Markdown

## Stage Checkpoints

- [ ] 分场结构表覆盖全部集数，每集含剧情目标、情感目标、场景和角色
- [ ] 镜头列表至少覆盖前 3 集（后续可在 implement 阶段细化）
- [ ] 时长分配精确到每集每个镜头，总时长在容差范围内
- [ ] 转场规划覆盖集内转场和集间衔接
- [ ] 6 个设计文档（3 通用 + 3 短剧专用）已写入 `build/`
- [ ] 无 WHAT/WHY 层面内容——场次目标引用自 spec，不在此重新定义
- [ ] 宪法合规检查已执行，偏差已记录

## 质量门禁

- 分场结构表的总集数 = spec 中定义的总集数？每集时长在目标值 ±5 秒内？
- 镜头列表的景别变化是否平滑？是否包含跳轴检查？
- 特写镜头占比是否达到宪法要求（≥ 30%）？
- 每集是否包含 hook 段 + 主体段 + 结尾段的三段式结构？
- 集间转场是否有明确的衔接逻辑（非硬性跳转）？
- 设计文档是否都包含详细的字段定义和填写说明（非空模板）？
- 是否包含 spec 中未定义的 WHAT/WHY 内容？（应无——若有，应移至 spec.md）

**下一步**：执行 `/specforge.tasks` 将创作计划分解为可执行的任务清单
