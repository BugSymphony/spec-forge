# 短剧规格编写

## User Input

```text
$ARGUMENTS
```

根据用户输入创建短剧功能规格文件。specify 阶段仅关注 **WHAT/WHY**（故事要讲什么、为什么要讲、为谁讲、规模多大），严格禁止涉及 HOW（怎么拍、镜头怎么设计、相机怎么放）。HOW 类的所有决策留给 plan 阶段。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目（存在 `.specforge/` 目录）
2. 执行 `specforge list --detail --json` 确认当前活动 feature 和项目上下文
3. 读取 `.specforge/constitution.md` 确保规格编写遵循宪法约束
4. 读取 `.specforge/templates/spec-template.md` 作为输出结构参考
5. 若用户已提供描述文本 `$ARGUMENTS`，解析其中的创作意图

## Outline

### 第 1 步：创建 Feature 目录

1. 若 `$ARGUMENTS` 非空，执行 `specforge new "$ARGUMENTS" --dry-run --json` 预览生成的 feature 名称和路径
2. 确认预览无误后，执行 `specforge new "$ARGUMENTS" --json` 创建 feature
3. 解析 JSON 输出，获取 `feature_dir` 和 `feature_name`
4. 若 feature 已存在，ERROR：提示用户使用 `specforge use <name>` 切换或调整描述文本

### 第 2 步：解析短剧创作意图

从 `$ARGUMENTS` 和人机对话中提取以下关键维度：

**故事层面**：
- **核心情节**：故事的核心冲突和剧情走向（1-2 句话）
- **人物关系**：主要角色及其关系网络（至少 2 个核心角色）
- **情感基调**：故事的整体情感色彩（甜/虐/爽/暖/燃/悬疑）
- **世界观背景**：故事发生的时代/场景/社会环境

**受众层面**：
- **目标观众**：核心观众群体的画像
- **观看场景**：用户观看短剧的典型场景（碎片时间/睡前/通勤）
- **情感共鸣点**：故事要触达的观众情感

**规模层面**：
- **总集数**：计划制作的集数范围
- **每集时长**：单集目标时长（秒）
- **总时长**：全剧总时长目标

若用户输入不足以覆盖上述维度，依次提问补充。每次只问一个最关键缺失维度，最多 3 轮。

### 第 3 步：定义故事梗概（100-200 字）

生成 100-200 字的故事梗概，包含以下要素：
- 故事的起点（初始状态和核心冲突）
- 关键转折点（剧情推动力）
- 情感核心（观众投入的情感锚点）
- 预期结局方向（不剧透具体结局，但给出情感方向）

**禁止内容**：
- 不写具体场次安排（那是 plan 的工作）
- 不写镜头描述或相机运动（那是 plan 的工作）
- 不写具体台词（那是 implement 的工作）

### 第 4 步：定义风格方向

定义短剧的整体风格方向，每个维度给出明确选择和理由：

1. **视觉风格**：整体视觉调性（如：明亮温暖/暗调冷峻/高饱和鲜艳/柔和低反差）
2. **节奏风格**：叙事节奏（如：快节奏反转/舒缓温情/张弛交替/紧凑悬疑）
3. **表演风格**：演员表演方向（如：自然生活化/夸张戏剧化/内敛克制/张扬外放）
4. **音乐风格**：配乐基调（如：轻快流行/深沉氛围/古典悠扬/电子节奏）

**禁止内容**：
- 不写具体镜头规格或设备要求
- 不写具体配乐曲目或音效清单

### 第 5 步：定义内容规模

填写明确的规模参数：

- **总集数**：计划制作的集数（如 30 集）
- **每集时长**：单集目标时长（秒，如 90 秒）
- **总时长**：全剧总时长（自动计算：总集数 × 每集时长）
- **核心角色数**：主要角色数量（建议 3-6 个）
- **主要场景数**：关键场景/地点的数量估算

内容规模数据写入 spec 模板的「内容规模」章节。

### 第 6 步：定义场次目标（最少 2 个）

场次目标（Episode Scene Goal）是短剧领域的 User Story 等价结构。每个场次目标描述一组关键场景对剧情推进和观众体验的价值。

每个场次目标包含：
- **标题**：简短摘要（如 "开场 hook —— 身份反转揭示"）
- **描述**：这个场次对剧情推进和观众体验的价值（3-5 句）
- **Why this priority**：解释为什么这个场次对剧情推进/观众体验最重要
- **Independent Test**：描述如何独立验证（如 "阅读该场次脚本后，能判断剧情信息是否有效传递，观众是否产生预期情感反应"）
- **Acceptance Scenarios**（Given-When-Then，最少 2 个）：
  - Given [观众已知的剧情信息]，When [场次中的关键镜头或对话事件]，Then [观众应获得的信息、理解或情感]

**场次目标示例结构**：

```markdown
### 场次目标 1 - 开场人物关系建立 (Priority: P1)

[描述：本场次在剧集开头快速建立核心人物关系和冲突背景，是观众决定是否继续观看的关键 hook 点]

**Why this priority**: 短剧前 3 秒决定留存率。本场次承载吸引观众的核心 hook，若未能有效建立人物关系和情感张力，观众将在 3 秒内流失。

**Independent Test**: 阅读本场次脚本和台词后，可在 10 秒默读中判断：人物关系是否清晰？核心冲突是否可感知？是否产生继续观看的欲望？

**Acceptance Scenarios**:

1. **Given** 观众对角色一无所知，**When** 开场 3 秒内呈现核心人物关系（如身份反差/情感对峙/意外相遇），**Then** 观众立即感知到核心冲突的存在并产生好奇心
2. **Given** 观众已感知到初始冲突，**When** 本场次结束时抛出第一个悬念或情感落点，**Then** 观众产生"接下来会怎样"的期待，愿意继续观看下一场
```

若用户仅提供 1 个场次目标或信息不完整，引导补充至少第 2 个（如高潮场次或结局情感落点）。最多定义 3-4 个场次目标。

**Priority 分配规则**：
- P1：开场 hook 场次——决定留存率，必须最先完成
- P2：情感高潮场次——承载核心情感释放
- P3：结局落点场次——决定观众满意度和传播意愿

### 第 7 步：定义核心要素

列出短剧创作的核心要素：

1. **核心冲突**：故事的主要矛盾（人物 vs 人物 / 人物 vs 环境 / 人物 vs 自我）
2. **情感主线**：贯穿全剧的情感线索
3. **节奏曲线**：整体节奏的情绪变化趋势描述（如 "前 5 集快速建立——中段情感升温——后段冲突爆发——结局情感和解"）
4. **风格识别点**：使本剧区别于其他同类型短剧的独特元素

**禁止内容**：
- 不写具体集数的剧情分配
- 不写镜头节奏设计（如 "第 3 场用快切"）
- 不写具体音乐或声音设计

### 第 8 步：定义成功标准

定义可衡量的短剧成功标准：

- **SC-001 叙事完整性**：故事梗概中的核心冲突在场景目标中均有对应，无未解决的情节线
- **SC-002 受众匹配度**：风格方向描述与目标受众画像一致，无风格冲突
- **SC-003 规模合理性**：总集数和每集时长在目标平台的最佳实践范围内
- **SC-004 场次独立性**：每个场次目标可独立验证，不依赖其他场次的上下文即可判断剧情价值
- **SC-005 情感传达可测性**：每个场次目标的 Acceptance Scenarios 中 Then 子句描述的是观众可感知的情感/信息，非抽象指标

### 第 9 步：记录假设与约束

列出当前阶段做出的假设和已知约束：

- 用户未明确指定的信息所做的默认假设
- 目标平台的技术约束（如时长限制、画幅比例）
- 预算或资源相关约束
- 内容审查或合规约束

### 第 10 步：写入规格文件

1. 定位 feature 目录：使用 `specforge show --paths-only` 获取路径
2. 读取 `.specforge/templates/spec-template.md` 获取短剧 spec 模板
3. 用第 2-9 步生成的内容填充模板各章节
4. 写入 `{feature_dir}/spec.md`
5. 执行 `specforge validate --stage specify --json` 校验规格完整性
6. 若校验失败，根据错误信息修正后重新写入

## Output

- **制品**：`{feature_dir}/spec.md`
- **格式**：Markdown
- **章节**：故事梗概 → 风格方向 → 内容规模 → 场次目标（最少 2 个）→ 核心要素 → 成功标准 → 假设与约束

## Stage Checkpoints

- [ ] 故事梗概 100-200 字，含起点、转折、情感核心、结局方向
- [ ] 风格方向覆盖视觉、节奏、表演、音乐四个维度
- [ ] 内容规模包含总集数、每集时长、总时长
- [ ] 场次目标至少 2 个，每个含 Why This Priority / Independent Test / Given-When-Then（最少 2 个 Given-When-Then）
- [ ] **无 HOW 类内容**：不包含镜头列表、相机位置、场次顺序安排、具体台词、音乐曲目
- [ ] 成功标准可衡量（SC-001 至 SC-005 均填有具体指标）
- [ ] 假设与约束记录清晰

## 质量门禁

- 故事梗概是否在 100-200 字范围内？
- 场次目标描述是否聚焦于"什么+为什么"而非"怎么拍"？
- 风格方向是否有明确的选择和理由，而非模糊描述？
- Acceptance Scenarios 的 Then 子句是否描述了观众可感知的结果？
- 内容规模数据是否具体可计算（总集数 × 每集时长 = 总时长）？
- 是否包含镜头列表、相机位置、设备规格等 HOW 类内容？（应无）
- 是否包含场次顺序或集数分配？（应无——那是 plan 的工作）

**下一步**：执行 `/specforge.clarify` 澄清规格中的模糊点，或执行 `/specforge.plan` 生成分场设计和拍摄方案
