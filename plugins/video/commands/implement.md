# 短剧实施

## User Input

```text
$ARGUMENTS
```

根据 tasks.md 定义的任务顺序，逐集编写短剧的分镜头脚本和台词本。最终产物写入 `dist/video/` 目录。短剧脚本是供下游 AI 视频生成工具使用的结构化输入——SpecForge 本身不渲染视频。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目（存在 `.specforge/` 目录）
2. 执行 `specforge list --detail --json` 确认当前活动 feature
3. 执行 `specforge validate --stage tasks --json` 确认 tasks.md 已通过校验
4. 若校验失败，ERROR：提示先完成 tasks 阶段后再执行 implement
5. 确认 `{feature_dir}/plan.md` 已包含完整的分场结构表、镜头列表和时长分配
6. 读取 `.specforge/constitution.md` 确认短剧宪法约束
7. 加载 `{feature_dir}/tasks.md` 获取任务执行顺序
8. 确认 `dist/video/` 目录可写入。若不存在，自动创建

## Outline

### 第 1 步：加载任务清单

1. 读取 `{feature_dir}/tasks.md` 获取完整任务列表
2. 按 phase 顺序执行任务：
   - Phase 1：Setup（项目结构初始化）
   - Phase 2：Foundational（共享模板和标准建立）
   - Phase 3+：各用户故事/场次目标对应的脚本编写
   - 最终 Phase：Polish（跨集统一检查和优化）
3. 记录当前正在执行的任务 ID 和进度

### 第 2 步：初始化输出目录

1. 检查 `dist/video/` 是否存在，若不存在则创建：
   ```bash
   mkdir -p dist/video
   ```
2. 创建输出目录结构：
   ```text
   dist/video/
   ├── 第01集-分镜头脚本.md
   ├── 第01集-台词本.md
   ├── 第02集-分镜头脚本.md
   ├── 第02集-台词本.md
   ├── ...
   ├── 第N集-分镜头脚本.md
   └── 第N集-台词本.md
   ```
3. 检查已有文件——若某集脚本已存在，跳过（增量创建，不覆盖已有成品）

### 第 3 步：加载模板和参考文档

从 `{feature_dir}/build/` 加载设计文档作为编写参考：

- `build/分镜头脚本模板.md` — 标准分镜脚本格式
- `build/场景布置方案.md` — 场景描述和布置细节
- `build/演员道具清单.md` — 角色造型和道具参考
- `build/contracts/` — 脚本格式合约
- `{feature_dir}/spec.md` — 故事梗概、风格方向（确保创作不偏离 WHAT/WHY）
- `{feature_dir}/plan.md` — 分场结构表、镜头列表、时长分配、转场规划

### 第 4 步：逐集编写分镜头脚本

按集数顺序（从第 01 集开始）编写每集的分镜头脚本。

#### 分镜头脚本格式

```markdown
# 第[N]集分镜头脚本：[场次标题]

**基本信息**
- 集数：第[N]集
- 场次标题：[标题]
- 目标时长：[X] 秒
- 剧情目标：[简述——来自 plan 分场结构表]
- 情感目标：[简述——来自 plan 分场结构表]
- 出场角色：[角色列表]
- 场景：[场景名称]

## 镜头序列

| 镜号 | 景别 | 时长(s) | 画面描述 | 动作/调度 | 对白/旁白参考 | 音效/音乐提示 | 备注 |
|------|------|--------|---------|----------|-------------|-------------|------|
| N01  | [景别] | [秒]    | [详细的画面描述，含构图、色调、关键视觉元素] | [演员动作方向、走位、相机运动] | [对白摘要或旁白内容摘要] | [音效类型或音乐情绪提示] | [特殊要求] |
```

#### 编写原则（遵循短剧宪法）

1. **Hook 优先**：每集前 3 个镜头（对应 hook 段）必须有最强的视觉冲击力或情感张力
2. **节奏控制**：严格按照 plan 中分配的时长，每镜时长偏差 < ±1 秒
3. **景别平滑**：相邻镜头景别变化不超过 2 级（如 LS→MCU 可，LS→CU 不可）
4. **视线连续**：同一场景内角色视线方向保持一致，对话双方视线相对
5. **情感递进**：每集的情感强度呈上升曲线，结尾达到情感峰值
6. **特写覆盖**：保证特写镜头占比 ≥ 30%

#### 对白/旁白编写规则

- 所有台词必须口语化——写完默读一遍检查自然度
- 禁止书面语、说教腔、信息堆砌
- 每句对白不超过 15 个字（短剧快节奏要求）
- 对白与留白比例约 6:4——给演员表演和观众消化留空间

### 第 5 步：逐集编写台词本

每集配套编写独立台词本，供演员录制使用。

#### 台词本格式

```markdown
# 第[N]集台词本：[场次标题]

**基本信息**
- 集数：第[N]集
- 场次标题：[标题]
- 角色列表：[角色名（扮演者）]
- 总台词句数：[数量]
- 关联分镜：第[N]集-分镜头脚本.md

## 台词序列

| 序号 | 镜号 | 角色 | 台词内容 | 情绪/语气 | 动作提示 | 时长(s) |
|------|------|------|---------|----------|---------|--------|
| L01  | N03  | [角色名] | [完整台词] | [高兴/悲伤/愤怒/平静…] | [同步动作] | [秒] |
| L02  | N04  | [角色名] | [完整台词] | [高兴/悲伤/愤怒/平静…] | [同步动作] | [秒] |
```

#### 台词编写规则

1. **情绪标注**：每句台词标注表演情绪和语气（如 "压抑怒气"、"强装镇定"、"喜极而泣"）
2. **动作同步**：标注说台词时的同步肢体动作（如 "转身背对"、"握紧拳头"、"推门而入"）
3. **时长估算**：按中文口语语速约 3-4 字/秒估算每句台词所需时长
4. **角色辨音**：不同角色的台词应有辨识度——用语习惯、句式长短、感叹词使用各不同
5. **口播检测**：检查是否有"信息播报"式台词——若台词听起来像在向观众解释剧情，重写为更自然的表达

### 第 6 步：实施中校验

每完成一集脚本，执行即时校验：

1. **时长校验**：所有镜头时长之和 = 目标时长（±5 秒容差）
2. **景别检查**：相邻镜头景别是否平滑过渡
3. **宪法检查**：
   - Hook 镜头是否在前 5 秒内出现？
   - 特写占比是否 ≥ 30%？
   - 结尾是否有悬念或情感落点？
   - 台词是否通过口语化默读测试？
4. **格式检查**：Markdown 表格结构完整，无缺失列

若校验失败，修正后重新校验，通过后再进入下一集。

### 第 7 步：跨集一致性检查

所有集数完成后，执行跨集一致性检查：

1. **角色连续性**：同一角色在不同集中的性格、语言习惯、外貌描述是否一致
2. **场景连续性**：同一场景在不同集中的空间描述、道具位置是否一致
3. **时间线一致性**：剧情事件的时间顺序是否合理，无时间线矛盾
4. **剧情连续性**：前后集的剧情是否衔接顺畅，无逻辑断点
5. **情感曲线一致性**：全剧情感曲线是否与 spec 中定义的节奏曲线匹配
6. **道具追踪**：关键道具的出现、使用、消失是否有合理交代

在 `dist/video/` 目录下生成 `跨集一致性报告.md`：

```markdown
# 跨集一致性报告

## 角色连续性
| 角色 | 检查项 | 结果 | 备注 |
|------|--------|------|------|
| [角色] | 语言习惯 | ✅/⚠️ | [说明] |

## 场景连续性
| 场景 | 检查项 | 结果 | 备注 |
|------|--------|------|------|

## 时间线
| 集数 | 事件 | 时间标记 | 结果 |
|------|------|---------|------|

## 剧情衔接
| 集间衔接 | 检查项 | 结果 |
|---------|--------|------|
```

### 第 8 步：更新任务状态

对 tasks.md 中已执行的任务标记完成：

1. 读取 `{feature_dir}/tasks.md` 当前内容
2. 将已完成的任务从 `- [ ]` 更新为 `- [x]`
3. 写入更新后的 tasks.md
4. 记录当前进度：已完成 / 总任务数

## Output

- **分镜头脚本**：`dist/video/第[N]集-分镜头脚本.md`（每集 1 个文件）
- **台词本**：`dist/video/第[N]集-台词本.md`（每集 1 个文件）
- **一致性报告**：`dist/video/跨集一致性报告.md`
- **格式**：Markdown（表格化镜头和台词序列）

## Stage Checkpoints

- [ ] `dist/video/` 目录已创建并包含所有集数的脚本文件
- [ ] 每集分镜头脚本包含完整的「基本信息」和「镜头序列」表格
- [ ] 每集台词本包含完整的「基本信息」和「台词序列」表格
- [ ] 每集时长校验通过（实际时长在目标值 ±5 秒内）
- [ ] 全剧特写镜头占比 ≥ 30%
- [ ] 跨集一致性报告已生成，所有检查项通过或标注风险
- [ ] tasks.md 已完成的任务已标记为完成
- [ ] 每次执行不覆盖已有脚本文件（增量创建）

## 质量门禁

- 每个分镜头脚本的镜头序列表格是否所有列都已填写？
- 每集前 3 个镜头是否承载了 Hook 功能？
- 每集最后一个镜头是否形成了悬念或情感落点？
- 台词本中每句台词是否包含情绪标注和动作提示？
- 台词是否通过口语化默读测试（读完不觉得生硬）？
- 景别变化是否平滑（相邻镜头不超过 2 级跳跃）？
- 角色台词是否有辨识度（不同角色开口风格不同）？
- 是否存在"信息播报"式台词（听起来像向观众解释剧情）？
- 跨集一致性报告是否覆盖了角色、场景、时间线、剧情、情感曲线、道具六个维度？

**下一步**：执行 `/specforge.review` 对成品进行观看体验评估和节奏审查
