# 短剧宪法管理

## User Input

```text
$ARGUMENTS
```

根据用户输入创建或修改 `.specforge/constitution.md` 短剧宪法文件。短剧宪法是短剧 SDD 工作流的基石，定义剧本创作的核心原则、制作标准、节奏准则和治理规则。所有后续阶段命令执行时必须遵循宪法约束。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目（存在 `.specforge/` 目录）
2. 执行 `specforge list --detail --json` 确认当前活动 feature 和项目上下文
3. 读取 `.specforge/templates/constitution-template.md` 作为输出结构参考
4. 若 `.specforge/constitution.md` 已存在，视为更新操作——保留已有原则，仅根据用户输入调整或补充

## Outline

### 第 1 步：解析用户输入

从 `$ARGUMENTS` 中提取短剧创作的关键信息：
- **剧集类型**：短剧的题材类型（甜宠/悬疑/逆袭/古装/都市/奇幻/轻喜剧/其他）
- **目标受众**：核心观众画像（年龄段、观看场景、审美偏好）
- **核心原则**：用户明确提出的不可妥协的创作理念或限制
- **制作标准**：用户提到的质量要求、发布标准
- **治理规则**：协作方式、修订流程、版本管理偏好

若用户输入为空，ERROR：提示用户提供短剧项目的目标描述或核心原则，例如 "本项目为面向 18-25 岁年轻女性的都市甜宠短剧，每集 60-90 秒，注重台词节奏和情感共鸣"

### 第 2 步：加载宪法模板

- 读取 `.specforge/templates/constitution-template.md` 获取结构
- 模板包含章节：`# [PROJECT_NAME] 创作宪法`、`## 核心原则`、`## 质量标准`、`## 治理规则`
- 短剧宪法在通用模板基础上，增加「制作标准」和「节奏准则」两大核心维度

### 第 3 步：定义核心原则（最少 3 条，建议 4-5 条）

引导用户定义短剧创作的核心原则。使用以下引导问题：

1. **第一条原则（最重要——剧本层面）**：这个短剧最不可妥协的叙事理念是什么？
   - 例如："每集必须有明确的情感钩子（hook），前 3 秒内抓住观众注意力"
   - 例如："情节推动必须由角色决策驱动，禁止依赖巧合或外部力量"
   - 例如："每集结尾必须有悬念或情感落点（cliffhanger），激励观众继续观看"

2. **第二条原则（视觉层面）**：短剧的视觉风格和镜头语言的核心准则？
   - 例如："所有镜头语言必须符合设定的风格基调（如甜宠→柔光暖调、悬疑→暗调冷色）"
   - 例如："特写镜头占比不低于 30%，确保演员微表情传达情感信息"
   - 例如："场景切换必须有视觉线索引导，禁止无动机跳切"

3. **第三条原则（节奏层面）**：短剧的节奏控制和质量底线？
   - 例如："每集时长偏差不超过 ±5 秒，确保平台播放标准化"
   - 例如："台词自然度检测——所有台词必须通过口语化朗读测试"
   - 例如："对白与留白的比例控制在 6:4，避免信息过载"

4. **第四条原则（可选——协作层面）**：团队协作或流程约束？
   - 例如："所有分镜脚本必须经过台词朗读测试后方可进入拍摄"
   - 例如："每集拍摄前必须有完整的场景布置清单和道具核查"

5. **第五条原则（可选——受众层面）**：对目标观众的承诺？
   - 例如："台词语言必须符合目标受众的语感，避免说教和书面语"
   - 例如："每集至少包含一个可独立传播的'名场面'片段"

每条原则包含三个部分：
- **原则名称**：简短摘要（1 句话）
- **描述**：具体说明（3-5 句），定义本原则的适用范围和判断标准
- **理由**：为什么这条原则对短剧项目质量至关重要

若用户未明确提供足够信息，基于短剧内容类型提供合理默认值，并标注为"建议原则——请审查确认"。

### 第 4 步：定义质量标准

列出适用于短剧所有 SDD 阶段制品的质量检查维度：

**通用标准（所有内容类型共享）**：
- **QS-001 完整性**：所有必填字段均已填写，无空占位符
- **QS-002 一致性**：上下游制品间无矛盾，术语统一
- **QS-003 可执行性**：任务描述具体可操作，含明确产出
- **QS-004 清晰性**：无歧义标记，成功标准可验证

**短剧专用标准**：
- **QS-005 节奏一致性**：镜头时长分配和转场节奏符合风格基调，每集时长偏差 < ±5 秒
- **QS-006 镜头连贯性**：相邻镜头间动作方向、视线方向、场景空间关系保持连续，无跳轴错误
- **QS-007 台词自然度**：所有台词通过口语化朗读测试，无书面语、说教腔、信息堆砌
- **QS-008 情感传达有效性**：关键情感节点（hook、转折、高潮、落点）的情感传达是否可被观众感知

### 第 5 步：设定制作标准

定义短剧制作的硬性技术规范：

**时长规范**：
- 单集时长标准（如 60 秒/90 秒/120 秒）
- 片头片尾时长分配
- 总集数范围和总时长目标

**输出规范**：
- 分镜头脚本格式标准
- 台词本格式标准
- 场景布置方案包含要素
- 演员道具清单包含要素

**品质检查**：
- 每集完成后的自查清单
- 跨集连续性检查（角色造型、场景道具、剧情逻辑）

### 第 6 步：设定治理规则

定义短剧宪法的修订流程和版本管理：

**修订流程**：
1. **提议**：任何贡献者可提交修订提案，说明动机和影响范围
2. **审查**：维护者评估合理性和对已有剧本的影响范围
3. **批准**：审查通过后合并修订，更新版本号
4. **传播**：同步更新所有受影响的集数脚本中的宪法引用

**版本管理**：使用 MAJOR.MINOR.PATCH 语义版本
- MAJOR：移除或重新定义已有原则（如改变剧集时长标准）
- MINOR：新增原则或制作标准
- PATCH：措辞澄清、示例更新

### 第 7 步：写入宪法文件

- 使用模板结构，用第 3-6 步的生成内容填充占位符
- 写入 `.specforge/constitution.md`
- 确保版本号设为 `1.0.0`，批准日期和最后修订日期为当前日期
- 若为更新操作：保留当前版本号，根据变更幅度递增

## Output

- **制品**：`.specforge/constitution.md`
- **格式**：Markdown
- **位置**：项目根目录 `.specforge/constitution.md`

## Stage Checkpoints

- [ ] 至少定义 3 条短剧创作原则，每条有名称、描述和理由
- [ ] 质量标准至少涵盖完整性、一致性、可执行性、清晰性四类 + 节奏一致性、镜头连贯性、台词自然度、情感传达有效性四类短剧专用标准
- [ ] 制作标准包含时长规范、输出规范和品质检查
- [ ] 版本号和日期已填写
- [ ] 宪法内容与短剧内容类型对齐
- [ ] 无模糊占位符残留

## 质量门禁

- 原则条目中的描述是否具体到可判断是否违规？
- 质量标准是否涵盖短剧特有的节奏一致性、镜头连贯性、台词自然度？
- 制作标准是否包含可执行的时长规范和输出规范？
- 治理规则是否包含修订流程和版本管理？
- 是否明确短剧的目标受众和题材类型？
- 每集 hook 和 cliffhanger 的质量标准是否可验证？
