# 文章宪法管理

## User Input

```text
$ARGUMENTS
```

根据用户输入创建或修改 `.specforge/constitution.md` 宪法文件。宪法是 SpecForge SDD 工作流的基石，定义了文章创作的核心写作原则、论证标准和治理规则。所有后续阶段的命令在执行时必须遵循宪法约束。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目（存在 `.specforge/` 目录）
2. 执行 `specforge list --detail --json` 确认当前活动 feature 和项目上下文
3. 读取 `.specforge/templates/constitution-template.md` 作为输出结构参考
4. 若 `.specforge/constitution.md` 已存在，视为更新操作——保留已有原则，仅根据用户输入调整或补充

## Outline

### 第 1 步：解析用户输入

- 从 `$ARGUMENTS` 中提取关键信息：
  - **文章类型**：议论文、说明文、评论、杂文、科普文等
  - **写作领域**：技术文档、文学评论、社会观察、学术论文等
  - **目标受众**：普通读者、专业人士、学术同行、决策者等
  - **核心主张**：用户明确提出的不可妥协的写作理念或论证限制
  - **质量标准**：用户提到的验收标准、发布要求、论证深度要求
- 若用户输入为空或过于模糊，ERROR：提示用户提供文章创作的核心方向或写作原则
  - 最小有效输入示例："面向技术管理者的深度分析文章，注重数据支撑和逻辑严密性"
  - 最小有效输入示例："面向大众的科普文章，要求通俗易懂、案例丰富"

### 第 2 步：加载宪法模板

- 读取 `.specforge/templates/constitution-template.md` 获取结构
- 模板包含以下核心章节：
  - `# [项目名] 创作宪法`
  - `## 写作原则`（含原则名称、描述和理由）
  - `## 论证标准`（含 QS-### 编号体系）
  - `## 治理规则`（修订流程和版本管理）
- 确认模板中所有占位符位置，记录需要填充的字段列表

### 第 3 步：定义写作原则（最少 3 条，建议 4-5 条）

引导用户定义文章写作核心原则。逐条使用以下引导框架：

1. **第一条原则（论点清晰性——最重要）**：
   - 引导问题：这篇文章最不可妥协的论证理念是什么？
   - 示例："核心论点必须在前三段明确陈述，禁止含糊其辞或隐藏立场"
   - 示例："每个论据必须直接服务于核心论点，禁止无关例证堆砌"
   - 反例检查：是否存在论点模糊仍可接受的情况？若存在，则原则需收紧

2. **第二条原则（论证严谨性）**：
   - 引导问题：文章的论证应达到什么标准？
   - 示例："所有关键主张必须提供数据支撑、文献引用或逻辑推演，禁止纯粹的主观断言"
   - 示例："论证链条必须完整覆盖主张→论据→推理→结论四环节，禁止跳步论证"
   - 反例检查：是否允许直觉性判断作为论证依据？明确边界

3. **第三条原则（读者导向）**：
   - 引导问题：文章与读者的关系应如何确立？
   - 示例："文章难度必须对齐目标受众的知识水平，术语首次出现时必须定义"
   - 示例："每个结论必须预见并回应至少一个可能的读者质疑"
   - 反例检查：是否允许作者以"我"为中心而无视读者预期？

4. **第四条原则（结构均衡性——可选）**：
   - 引导问题：文章的结构应遵循什么节奏？
   - 示例："引言不超过全文 10%，论证主体占 60-70%，结论占 10-15%"
   - 示例："每个段落聚焦单一论证点，段落间过渡需有逻辑衔接句"

5. **第五条原则（语言风格——可选）**：
   - 引导问题：文章的文体风格如何定义？
   - 示例："面向技术管理者的文章：专业术语可保留但需简洁解释；避免口语化"
   - 示例："面向大众的科普文章：用比喻和故事替代公式；句式短小，主动语态优先"

每条原则包含三个部分：
- **原则名称**：简短摘要（1 句话）
- **描述**：具体说明（3-5 句），定义本原则的适用范围和判断标准
- **理由**：为什么这条原则对文章质量至关重要

若用户未明确提供足够信息，基于文章类型提供合理默认值，并标注为"建议原则——请审查确认"。

### 第 4 步：定义论证标准

列出适用于所有 SDD 阶段制品的质量检查维度，使用 QS-### 编号：

**通用标准（所有类型共用）**：
- **QS-001 完整性**：所有必填字段均已填写，无空占位符
- **QS-002 一致性**：上下游制品间无矛盾，术语统一
- **QS-003 可执行性**：任务描述具体可操作，含明确产出
- **QS-004 清晰性**：无歧义标记，成功标准可验证

**文章特有标准**：
- **QS-005 论点鲜明性**：核心论点在第一段落明确可识别，无含糊表述；论点是否在文章中一以贯之
- **QS-006 论证完整性**：每个论证要点包含主张→证据→推理→结论的完整链条；引用来源可追溯验证
- **QS-007 逻辑一致性**：前后论点无自相矛盾；段落间逻辑过渡自然无跳跃；无逻辑谬误（以偏概全、偷换概念、因果倒置等）
- **QS-008 读者适配性**：语言难度匹配目标受众；专业术语均有定义或解释；预期读者质疑已得到回应

### 第 5 步：设定治理规则

定义宪法的修订流程和版本管理：

**修订流程**：
1. **提议阶段**：任何贡献者可在宪法执行中发现原则缺陷或缺失时提交修订提案
   - 提案须包含：改动动机、影响范围分析、修改后的完整条文
2. **审查阶段**：维护者评估提案的合理性和对已有制品的影响
   - 审查要点：是否与现有原则冲突、是否可验证、是否确实提升文章质量
3. **批准阶段**：审查通过后合并修订
   - MAJOR 修订需说明迁移方案
4. **传播阶段**：同步更新依赖制品的宪法引用
   - 列出受影响的制品清单，逐项确认是否需要更新

**版本管理**：使用 MAJOR.MINOR.PATCH 语义版本
- MAJOR：移除或重新定义核心写作原则
- MINOR：新增原则或论证标准条目
- PATCH：措辞澄清、示例更新、非语义修正
- 当前版本号：`1.0.0`

**冲突解决**：
- 宪法与具体文章需求冲突时：宪法优先，但可通过修订流程调整宪法
- 原则之间可能存在的张力（如论证严谨性 vs 读者可读性）需在分阶段执行时按权重权衡
- 宪法原则的优先级：论点清晰性 > 论证严谨性 > 读者导向 > 结构均衡性 > 语言风格

### 第 6 步：定义内容规模约束

根据文章类型定义规模约束建议（作为非强制参考）：

- **短篇评论 / 观点文**：800-2000 字，3-5 个论证要点，2-4 个引用来源
- **深度分析 / 行业观察**：2000-5000 字，5-8 个论证要点，5-10 个引用来源
- **学术论文 / 研究报告**：5000-12000 字，8-15 个论证要点，15-30 个引用来源

以上为建议范围，由用户根据项目实际需求决定。若用户未指定，默认按短篇评论处理。

### 第 7 步：写入宪法文件

- 使用模板结构，用第 3-6 步的生成内容填充占位符
- 写入 `.specforge/constitution.md`
- 版本号设为 `1.0.0`（新建）或递增（更新）
- 最后修订日期设为当前日期（YYYY-MM-DD 格式）
- 验证检查：所有原则是否含名称、描述和理由？论证标准是否含 QS 编号？
- 若为更新操作：保留当前版本号，根据变更幅度递增
  - 追加一条修订记录：版本号、日期、变更摘要

## Output

- **制品**：`.specforge/constitution.md`
- **格式**：Markdown
- **位置**：项目根目录 `.specforge/constitution.md`

## Stage Checkpoints

- [ ] 至少定义 3 条写作原则，每条有名称、描述和理由
- [ ] 论证标准涵盖通用 4 类（完整性、一致性、可执行性、清晰性）和文章特有 4 类（论点鲜明性、论证完整性、逻辑一致性、读者适配性）
- [ ] 版本号和日期已填写
- [ ] 宪法内容与文章创作领域对齐
- [ ] 无模糊占位符残留
- [ ] 写作原则按优先级排序，核心原则位置最前

## 质量门禁

- 原则条目中的描述是否具体到可判断是否违规？
- 论证标准是否涵盖论点识别、证据验证、逻辑检验、读者适配四个文章特有维度？
- 治理规则是否包含修订流程、版本管理和冲突解决机制？
- 规模约束是否按文章类型分级且可度量？
- 所有写作原则是否体现了"论点导向、论证严谨、读者为本"的文章创作理念？

**下一步**：执行 `/specforge.specify` 基于本宪法编写文章规格说明
