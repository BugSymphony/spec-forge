# 文章实施计划

## User Input

```text
$ARGUMENTS
```

根据文章规格说明（spec.md）生成实施计划（plan.md），包含论证逻辑链设计、引用清单规划和段落大纲。本阶段仅回答 **HOW**（怎么写），承接 spec 阶段的 WHAT/WHY，为 tasks 阶段提供可执行方案。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目（存在 `.specforge/` 目录）
2. 执行 `specforge list --detail --json` 确认当前活动 feature
3. 执行 `specforge show --artifact spec` 读取规格说明内容
4. 若尚未创建 spec.md，ERROR：提示先执行 `/specforge.specify`
5. 执行 `specforge setup plan --json` 初始化 plan 环境
   - 确认 plan.md 及其他设计文档模板已就位
   - 确认 `build/` 目录已创建（若不存在则创建）
6. 读取 `.specforge/templates/plan-template.md` 获取计划模板结构
7. 读取 `.specforge/constitution.md` 获取宪法约束进行合规检查

## Outline

### 第 1 步：解析 spec 中的 WHAT/WHY 输入

从 spec.md 中提取关键信息，作为 plan 设计的输入：

- **核心论点**：从 spec 的核心论点段落提取
- **论证要点清单**：从 spec 的论证要点章节提取所有要点及其优先级
- **目标受众**：受众定义（知识水平、阅读场景、关注点）
- **内容规模**：字数范围、段落数、引用数量要求
- **参考来源**：已确认和待确认的参考文献清单
- **成功标准**：SC 编号条目
- **宪法约束**：写作原则和论证标准条目

确认所有输入完整——若 spec 中仍有 `[NEEDS CLARIFICATION]` 标记，优先处理澄清：
- 能合理推断的 → 在 plan 中明确记录推断结果和推断依据
- 无法合理推断的 → 评估对论证链设计的影响：
  - 若影响 ≤ 1 个论证要点，可在 plan 中标注"待补充"并继续
  - 若影响核心论点或多个论证要点，ERROR：提示先执行 `/specforge.clarify`

### 第 2 步：设计论证逻辑链

设计从核心论点到各论证要点再到结论的完整逻辑链条。论证逻辑链是文章的内在推理结构，决定论点的展开顺序。

**论证链类型选择**：
根据 spec 中论证要点的特性，选择最适合的论证链类型：

- **递进式论证链**（适用于层层深入的论题）：
  - 结构：背景 / 问题 → 浅层分析 → 深层分析 → 核心论证 → 推论与启示
  - 适用场景：论证要点之间存在从一般到特殊、从表象到本质的逻辑递进关系
  - 判断标准：后一个要点是否以前一个要点的结论为前提？

- **并列式论证链**（适用于多角度论证的论题）：
  - 结构：核心论点 → 角度 A（数据层面）→ 角度 B（理论层面）→ 角度 C（案例层面）→ 综合结论
  - 适用场景：论证要点各自独立支撑核心论点，无需前提依赖
  - 判断标准：各要点是否可分别独立论证而不影响其他要点的有效性？

- **正反合论证链**（适用于存在强对立观点的论题）：
  - 结构：正方立场阐述 → 反方立场最有力论证 → 综合立场（正反合的调和）→ 结论
  - 适用场景：目标受众存在明显的预设立场，需要先承认对方合理性再推进论证
  - 判断标准：受众是否对该论题有强先入之见？

- **问题-解决论证链**（适用于实务性论题）：
  - 结构：问题定义与严重性论证 → 原因分析 → 解决方案论证 → 可行性评估 → 行动建议
  - 适用场景：论题面向决策者，最终目标是推动行动
  - 判断标准：文章的根本目的是否为提出或评估解决方案？

**论证链设计文档**（输出到 `build/argument-chain.md`）：
```
# 论证逻辑链

## 所选类型：[递进式/并列式/正反合/问题-解决]
### 选择理由

## 论证链条
[用 graphviz DOT 语法或 ASCII 图示表示]
论点 A → 论据 1 → 推理桥接 → 论据 2 → 综合 → 结论

## 关键过渡
- [论点 A] → [论点 B] 的过渡逻辑：[一句话说明衔接逻辑]
- [论点 B] → [结论] 的过渡逻辑：[一句话说明衔接逻辑]

## 潜在逻辑薄弱点
- [节点] 的推理依赖 [前提] → 若该前提不成立，则 [影响评估]
```

### 第 3 步：规划引用清单

将 spec 中的参考来源矩阵化为可执行的引用清单，按论证要点分配：

**引用分类与分配**：
- 对每个论证要点，列出所需的引用类型和数量
- 引用类型：
  - **实证数据**：统计报告、调研数据、实验数据
  - **权威观点**：专家论述、知名机构声明、同行评议论文
  - **案例佐证**：具体案例、历史实例、对比案例
  - **理论框架**：理论模型、分析框架、概念工具
  - **反驳材料**：反面观点原文、质疑论据（用于正反合论证链）

**引用质量标准**（按文章类型）：
- 学术文章：80% 以上来源为同行评议期刊或学术出版社
- 行业分析：50% 以上来源为一手数据和权威机构报告
- 大众科普：所有统计数据和科学声明需标注可查证的原始出处

**引用格式要求**：
- 若文章面向学术读者：采用标准学术引用格式（如 APA / MLA / GB/T 7714）
- 若文章面向大众读者：采用超链接或文内简述格式（如"根据 XX 机构 2024 年报告"）

**引用清单文档**（输出到 `build/citation-plan.md`）：
```
# 引用清单

## 已确认引用
| 编号 | 来源 | 类型 | 支撑论证要点 | 引用位置（段落） | 状态 |
|------|------|------|-------------|-----------------|------|
| C01 | [来源名] | 实证数据 | 论证要点 1 | 第 X 段 | 已获取 |
| C02 | [来源名] | 权威观点 | 论证要点 2 | 第 Y 段 | 待检索 |

## 待补充引用
| 编号 | 需求描述 | 类型 | 支撑论证要点 | 检索关键词 | 截止状态 |
|------|---------|------|-------------|-----------|---------|
| C0X | [需要什么数据] | [类型] | [哪个要点] | [搜索词] | 待检索 |

## 引用密度检查
- 每个论证要点最少引用数：____（确保每个要点有据可依）
- 单个段落最大引用数：____（避免引用堆砌）
- 全文引用总数目标：____（对齐成功标准）
```

### 第 4 步：设计段落大纲

将论证逻辑链转化为具体的段落大纲。每个段落定义其核心任务和内容要素。

**段落设计原则**：
- 每段一个核心论证任务（One Paragraph, One Point）
- 段落长度对齐内容规模约束（如 300-500 字/段）
- 段落间有逻辑过渡（不得出现"跳跃段落"）
- 引言段和结论段单独定义，不计入主体段落数

**段落大纲文档**（输出到 `build/paragraph-outline.md`）：
```
# 段落大纲

## 引言段（1 段）
- **核心任务**：引出论题，建立读者兴趣，陈述核心论点
- **内容要素**：背景铺垫 / 问题引入 / 论点陈述
- **估计字数**：____ 字

## 主体段 1：[段落任务摘要]
- **核心任务**：[本段要完成的一个论证子任务]
- **所属论证要点**：[论证要点 N]
- **内容要素**：[主张是什么] / [使用的证据类型] / [推理步骤]
- **关键引用**：[C0X, C0Y]
- **衔接逻辑**：[如何从上一段过渡到本段]
- **估计字数**：____ 字

## 主体段 2：[段落任务摘要]
- （同上结构）

## ...

## 结论段（1 段）
- **核心任务**：总结论证，重申论点，给出启示或行动建议
- **内容要素**：论证回顾 / 论点重述 / 延展思考
- **禁止事项**：不得引入新的论证要点
- **估计字数**：____ 字

## 段落数统计
- 引言：1 段
- 主体：N 段
- 结论：1 段
- 合计：N+2 段
- 预估总字数：____ 字（对齐 spec 规模约束：____ 字）
```

### 第 5 步：宪法合规检查

对照宪法进行合规检查——GATE：必须全部通过才能进入第 6 步。

**逐条原则检查**：
1. **论点清晰性**：核心论点是否在计划的引言段位置被明确安排？段落大纲中的每个主体段是否服务于同一个核心论点？
2. **论证严谨性**：每个论证要点是否安排了充分的引用支撑（引用清单检查）？论证链中是否有逻辑漏洞（薄弱点文档中的条目是否已处理）？
3. **读者导向**：段落大纲是否考虑了目标受众的知识水平（术语定义安排）？是否安排了回应读者质疑的段落（正反合或有反问环节）？
4. **结构均衡性**：段落分配是否符合宪法比例建议？引言/主体/结论的比例是否合理？
5. **语言风格**：段落大纲中是否明确了与目标受众匹配的语言风格约束？

**论证标准逐条检查**：
- QS-005 论点鲜明性：核心论点在段落大纲中是否有明确位置？
- QS-006 论证完整性：每个论证要点是否安排了完整的"主张→证据→推理→结论"？
- QS-007 逻辑一致性：论证链中是否有自相矛盾的安排？
- QS-008 读者适配性：是否有针对受众水平的适配设计？

**违规处理**：
- 若存在违规：记录违规条目、影响范围和改进建议到 plan.md 的 Complexity Tracking 表格
- 若违规无法在本计划中解决：标记为 `[CONSTITUTION GAP]`，转入宪法修订流程

### 第 6 步：生成技术上下文

填充 plan.md 的技术上下文部分（文章版）：

- **Language/Version**：中文写作 / 根据受众确定语言层次
- **Primary Dependencies**：核心引用来源清单（引用数量和类型分布）
- **Storage**：`dist/article/<标题>.md`
- **Testing**：人工审查 + 自动校对工具（如语法检查、引文格式校验）
- **Target Platform**：目标发布渠道（如微信公众号 / 知乎 / 个人博客 / 学术期刊）
- **Project Type**：文章（Article）
- **Performance Goals**：可读性评分（如 Flesch 可读性指数）、逻辑一致性 100% 通过
- **Constraints**：字数范围、引用数量下限、读者适配性 ≥ 4/5
- **Scale/Scope**：N 个主体段落、N 个引用来源、预估总字数

### 第 7 步：写入计划文件

- 读取 `.specforge/templates/plan-template.md` 获取结构
- 将第 2-6 步的生成内容填充模板
- 主要填入 `specs/<NNN>-<name>/plan.md` 的相应章节：
  - Summary：核心论点 + 论证链类型选择理由
  - Technical Context：文章技术参数
  - Constitution Check：合规检查结果
  - Project Structure：文档结构（含 build/ 子目录和设计文档清单）
  - Complexity Tracking：如有违规，记录于此
- 设计文档写入：
  - `build/argument-chain.md` — 论证逻辑链
  - `build/citation-plan.md` — 引用清单
  - `build/paragraph-outline.md` — 段落大纲

### 第 8 步：质量自检

1. **spec 对齐检查**：
   - 论证链是否覆盖了 spec 中所有论证要点（一一对应）？
   - 段落数是否在 spec 的规模约束范围内？
   - 引用数量是否满足 spec 的最小引用要求？

2. **HOW 边界检查**：
   - plan 中是否混入了 WHAT/WHY 类内容（如重新定义论点、重新评估受众优先级）？
   - plan 的核心产出是否聚焦于"如何组织"（论证链、段落分配、引用安排）？

3. **可执行性检查**：
   - 段落大纲是否足够详细，使 implement 阶段可直接执行？
   - 引用清单中的"待检索"条目是否有明确的检索策略（关键词、数据库）？
   - 论证链是否存在 implement 阶段无法解决的逻辑漏洞？

## Output

- **主要制品**：`specs/<NNN>-<name>/plan.md`
- **设计文档**：
  - `build/argument-chain.md` — 论证逻辑链设计
  - `build/citation-plan.md` — 引用清单规划
  - `build/paragraph-outline.md` — 段落大纲
- **格式**：Markdown
- **位置**：当前活动 feature 目录下

## Stage Checkpoints

- [ ] 论证链类型选择有明确理由，与 spec 论证要点特性对齐
- [ ] 论证逻辑链完整覆盖所有论证要点，无断裂或跳跃
- [ ] 引用清单按论证要点分配，含已确认和待检索条目
- [ ] 段落大纲每个段落定义核心任务和内容要素
- [ ] 段落总数和预估字数在 spec 规模约束范围内
- [ ] 段落间定义了逻辑过渡衔接
- [ ] 宪法合规检查全部通过（或违规已记录到 Complexity Tracking）
- [ ] 所有设计文档已输出到 build/ 目录

## 质量门禁

- 论证链是否可以独立于原文被评审（一个独立读者能否看懂论证逻辑）？
- 每个论证要点在段落大纲中是否有对号入座的段落？
- 引用清单中的每条引用是否标注了所属论证要点和预计段落位置？
- 段落大纲是否含足够细节支持按段落级别（而非大块级别）执行 implement？
- 宪法检查的违规项是否有合理理由且记录在案？

**下一步**：执行 `/specforge.tasks` 基于本计划生成任务清单
