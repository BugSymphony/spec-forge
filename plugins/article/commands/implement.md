# 文章实施撰写

## User Input

```text
$ARGUMENTS
```

按实施计划（plan.md）和段落大纲逐段撰写文章，将成品输出到 `dist/article/<标题>.md`。逐段执行、逐段自检，每完成一段标记任务状态。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目（存在 `.specforge/` 目录）
2. 执行 `specforge list --detail --json` 确认当前活动 feature
3. 执行 `specforge show --artifact tasks` 读取任务清单，确定当前执行阶段
4. 执行 `specforge validate --stage plan --json` 确认 plan 阶段已完成
   - 若 plan 不存在：ERROR 提示先执行 `/specforge.plan`
5. 读取以下关键文件：
   - `specs/<NNN>-<name>/spec.md` — 核心论点、论证要点、成功标准
   - `specs/<NNN>-<name>/plan.md` — 论证链和流程约束
   - `build/argument-chain.md` — 论证逻辑链
   - `build/citation-plan.md` — 引用清单
   - `build/paragraph-outline.md` — 段落大纲
6. 确保 `dist/article/` 目录存在（若不存在则创建）
7. 若 `dist/article/<标题>.md` 已存在：
   - 检查已有内容——是否已完成部分段落？
   - 若已有部分内容：从下一个未完成的段落继续（增量撰写，不覆盖已完成段落）
   - 若已全部完成但用户要求重写：备份旧版后开始新写

## Outline

### 第 1 步：确定文章标题

- 从 spec.md 中提取核心论点，精简为文章标题
- 标题要求：
  - 含核心论点关键词（让读者一眼了解文章立场）
  - 不超过 25 个汉字
  - 不使用疑问句标题（论点型文章应有明确立场）
  - 不使用标题党式震惊体
- 若用户输入 `$ARGUMENTS` 中含标题建议，优先采用
- 若无法确定标题：从核心论点中提取主谓宾结构精简为标题
- 示例：
  - ✅ "远程办公削弱企业创新能力的三重机制"
  - ✅ "为何火星殖民计划需要重新评估"
  - ❌ "震惊！远程办公居然会导致这个问题"（标题党）
  - ❌ "远程办公真的会降低创新吗？"（疑问句，无立场）

### 第 2 步：撰写引言段

根据段落大纲中的引言段定义撰写。

**撰写流程**：
1. 重新阅读 spec 中的核心论点、目标受众定义和论证要点 P1
2. 回顾 paragraph-outline.md 中引言段的内容要素清单
3. 按以下结构撰写引言段：
   - **开篇钩子**（1-2 句）：引起读者兴趣——可用的技巧：
     - 惊人的数据或事实
     - 一个反直觉的现象
     - 一个读者可能面临的困境
     - 注意：钩子必须与核心论点直接相关，禁止无关噱头
   - **背景铺垫**（2-3 句）：为不熟悉主题的读者建立必要背景
     - 根据目标受众知识水平调整深度
     - 面向专家受众可精简，面向大众需更多铺垫
   - **论点陈述**（1-2 句）：明确陈述核心论点
     - 论点句应加粗或放在段落末尾的醒目位置
     - 论点句需包含主张方向（"X 导致 Y"、"A 优于 B"、"P 应以 Q 方式重新理解"）
   - **文章路线图**（1 句）：预告文章结构（但不要逐段罗列——一个概括句即可）

4. **自检引言段**：
   - 论点是否在引言段中明确可识别？
   - 读者读完引言段是否能判断文章立场？
   - 字数是否在段落大纲的估计范围内？
   - 是否使用了与目标受众适配的语言风格？

### 第 3 步：逐段撰写主体段落

按段落大纲中的主体段顺序逐段执行。对每个主体段落：

**段落撰写步骤**：
1. 重新阅读该段落在 paragraph-outline.md 中的定义：
   - 核心任务
   - 所属论证要点
   - 内容要素
   - 关键引用编号
   - 衔接逻辑
2. 检查 citation-plan.md 中分配给本段落的引用：
   - 确认引用材料已获取（"已获取"状态）
   - 若引用状态为"待检索"：先执行检索获取引用材料，更新 citation-plan.md 状态为"已获取"
   - 若检索失败（信息不可得）：标注替代引用或修改段落论证方式
3. 检查 argument-chain.md 中本段落在论证链中的位置：
   - 确认与前一段的过渡逻辑
   - 确认与后一段的过渡预设
4. 撰写本段内容：
   - **主题句**（1 句）：本段核心主张，直接服务于所属论证要点
   - **证据呈现**（2-4 句）：引用数据、案例或权威观点
     - 每个引用在文内使用统一格式标注
     - 数据和统计须含具体数字和来源年份
   - **推理解释**（2-4 句）：解释证据如何支撑主题句的主张
     - 禁止"显而易见"式跳步——必须写出推理过程
     - 允许使用因果逻辑、类比推理、排除法等推理方式
   - **段落收束**（1 句）：回扣主题句或建立与下一段的过渡桥接
5. **自检本段落**：
   - 是否聚焦单一论证任务（无跑题）？
   - 主张—证据—推理—结论链条是否完整？
   - 引用是否准确标注来源？
   - 字数是否在段落大纲估计范围内？
   - 与前一段的衔接是否自然？

**逐段质量控制**：
- 每完成一段，回读上一段确认过渡自然
- 每完成一个论证要点的所有段落，验证该要点的论证完整性：
  - 该论证要点是否已被完整支撑？
  - 是否遗漏 spec 中该要点的任何 Acceptance Scenario？
- 若发现论证链偏差（写偏了）：回到 argument-chain.md 定位偏差点，修正后继续

**并行段落策略**：
段落撰写需按论证链顺序执行（不可乱序），但以下任务可与撰写并行：
- 引用检索（可在撰写前预先完成所有"待检索"引用）
- 数据和案例验证（校对引用准确性）

### 第 4 步：撰写结论段

根据段落大纲中的结论段定义撰写。

**撰写原则**：
- **不做新论证**：结论段不得引入任何新的论证要点或引用
- **不简单重复**：换一个角度或高度重新表达核心论点
- **给出延伸**：1-2 句延展思考——论点成立后的启示或建议
- **不含歉语**：禁止"才疏学浅"、"抛砖引玉"、"水平有限"等自谦词（文章以论证品质说话）

**结论段结构**：
1. **论证回顾**（1-2 句）：概括全文的论证链条（不是逐段复述）
2. **论点重述**（1 句）：用不同于引言的方式重述核心论点
3. **延伸思考**（1-2 句）：论点成立后的意义、启示或行动建议
   - 启示必须与核心论点有直接逻辑关联——禁止无关发散
4. **开放收尾**（1 句）：为读者留思考空间（可选）

**自检结论段**：
- 是否含有新的论证要点？（如有则移除）
- 读者只看引言 + 结论能否把握文章主旨？
- 延展思考是否与核心论点直接相关？

### 第 5 步：引用格式统一与验证

对全文引用的格式进行统一和验证：

**格式统一**：
- 根据文章发布平台确定引用格式：
  - 学术平台：文内引用格式统一（如 `(Author, Year)` 或 `[1]`）
  - 大众平台：超链接格式 + 文末参考文献列表
  - 社交媒体：简洁文内标注（"据XX机构2024年报告"）
- 确保所有引用格式一致——不得混用两种引用风格

**引用验证**（逐条检查）：
- 网址是否可访问（若含 URL）
- 来源年份、作者名、机构名是否准确
- 数据摘录是否与原文一致（抽查 30% 的引用）
- 是否存在断链或失效引用（标记为"已失效"）

**验证结果记录**：
- 在 citation-plan.md 中更新每条引用的验证状态
- 发现不准确引用 → 修正或替换

### 第 6 步：整体通读与打磨

完成所有段落后，整体通读全文：

**通读检查清单**：
1. **论证链流畅度**：从头到尾通读，标注任何感到跳跃或断裂的过渡处
2. **逻辑一致性**：检查全文是否存在前后矛盾的主张
   - 特别关注：结论与引言是否一致？各论证要点间是否有隐性冲突？
3. **重复检测**：标记重复使用的措辞、重复出现的论证、重复引用的数据
   - 同一引用在不同段落出现：需在不同段落中用不同角度解读，而非简单复述
4. **读者体验**：以目标受众身份重新阅读，评估：
   - 难度是否适配？（术语是否有解释？）
   - 节奏是否恰当？（密集论证段是否需要间插例证缓冲？）
   - 是否会中途弃读？（最可能在哪段丢失读者？）
5. **字数统计**：实际字数是否在 spec 规模约束范围内（±20%）
   - 若超出：优先精简重复内容和冗余修饰
   - 若不足：检查是否有论证要点未充分展开

**打磨操作**：
- 修缮粗糙过渡：在段落衔接处添加过渡句
- 精简冗余：每个段落回检——是否有可删除而不影响论证的句子？
- 强化钩子：引言段的开篇是否能更强有力？
- 统一术语：确保同一概念在全文使用同一术语

### 第 7 步：写入成品文件

- 将完成的内容写入 `dist/article/<标题>.md`
- 文件头部添加 YAML 元数据：
  ```yaml
  ---
  title: [文章标题]
  created: [完成日期]
  planned_by: specs/<NNN>-<name>/plan.md
  spec: specs/<NNN>-<name>/spec.md
  words: [实际字数]
  paragraphs: [实际段落数]
  citations: [引用数量]
  ---
  ```
- 若为增量撰写（第 2+ 次执行 implement）：
  - 保留文件中已有内容
  - 追加新完成的段落
  - 更新 YAML 元数据中的 `updated` 字段和字数统计
- 同步更新 tasks.md：将已完成任务标记为 `[x]`

### 第 8 步：成功标准自评

对照 spec.md 中的 SC 条目进行自评：

- **SC-001 论点清晰度**：引言段的论点是否清晰可识别？第三者可复述？
- **SC-002 论证说服力**：每个论证要点是否满足"主张→证据→推理→结论"链条？
- **SC-003 读者适配度**：语言难度是否匹配目标受众？
- **SC-004 引用可追溯性**：所有引用是否可追溯原始出处？
- **SC-005 内容规模达标**：字数是否在 ±20% 范围内？

逐条评分（通过 / 部分通过 / 未通过），记录到 plan.md 的追加章节。

## Output

- **制品**：`dist/article/<标题>.md`
- **格式**：Markdown（含 YAML 元数据头）
- **位置**：项目根目录 `dist/article/` 目录下
- **任务清单更新**：`specs/<NNN>-<name>/tasks.md` 中已完成任务的 `[ ]` 改为 `[x]`

## Stage Checkpoints

- [ ] 文章标题含核心论点关键词，不超过 25 字
- [ ] 引言段含开篇钩子、背景铺垫、明确论点和路线图
- [ ] 每个主体段落含主题句、证据呈现、推理解释、段落收束
- [ ] 每个论证要点在 1+ 段落中完整展开，满足 spec 中的 Acceptance Scenarios
- [ ] 结论段不含新论证、不含自谦语，含延伸思考
- [ ] 引用格式全文统一，来源可追溯验证
- [ ] 全文字数在 spec 规模约束范围内（±20%）
- [ ] 整体通读无逻辑跳跃或前后矛盾
- [ ] 成品文件头部含完整 YAML 元数据
- [ ] tasks.md 中对应任务已标记完成

## 质量门禁

- 是否每个段落都只聚焦一个核心论证任务？
- 是否每个引用都有明确的文内来源标注？
- 是否没有段落出现"主张缺失"（有证据无主张）或"证据缺失"（有主张无证据）？
- 论证链从头到尾是否有逻辑断裂？
- 文章成品是否可以脱离 spec/plan 被独立阅读和评价？

**下一步**：执行 `/specforge.review` 对成品进行逻辑一致性和可读性审查
