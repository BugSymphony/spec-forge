# Tasks: [文章标题]

**Input**: 设计文档 `specs/[###-feature-name]/build/` + `spec.md` + `plan.md`

**Prerequisites**: plan.md (required), spec.md (required for spec compliance), argument-chain.md, citation-plan.md, paragraph-outline.md

**Organization**: 任务按文章撰写流程组织：准备 → 引言 → 逐段主体 → 结论 → 润色。每个主体段落为独立可执行任务。

## Format: `[ID] [P?] [Phase] Description`

- **[P]**: 可并行执行（不同段落或独立任务，无相互依赖）
- **[Phase]**: 所属阶段（PREP / INTRO / BODY / CONCL / POLISH）
- 包含明确文件路径和输出目标

---

## Phase 1: 准备阶段 (Preparation)

**Purpose**: 引用材料收集与验证，确保撰写前所有信息就位

- [ ] T001 核对 citation-plan.md 中所有"待检索"引用，通过学术数据库/搜索引擎检索并获取原文
- [ ] T002 [P] 验证所有"已获取"引用的来源可追溯性（URL 可访问 / 文献可查）
- [ ] T003 [P] 阅读并消化所有引用材料，标注每个引用中的关键段落和数据
- [ ] T004 确认 `dist/article/` 目录存在，若不存在则创建
- [ ] T005 [P] 复核 spec.md 中核心论点与论证要点，确认无遗漏的 [NEEDS CLARIFICATION] 标记

**Checkpoint**: 所有引用材料已就位并可追溯，撰写可开始

---

## Phase 2: 引言段 (Introduction)

**Purpose**: 撰写引言段——文章的第一印象和论点锚点

- [ ] T006 根据 paragraph-outline.md 的引言段定义，撰写开篇钩子（1-2 句）
- [ ] T007 撰写背景铺垫（2-3 句），对齐目标受众知识水平
- [ ] T008 撰写核心论点陈述（1-2 句），确保可识别性和立场明确
- [ ] T009 撰写文章路线图（1 句），概括论证方向但不逐段罗列
- [ ] T010 自检引言段：论点清晰可识别？字数在规划范围内？语言适配目标受众？
- [ ] T011 将引言段写入 `dist/article/[标题].md`，添加 YAML 元数据头

**Checkpoint**: 引言段完成——读引言即可判断文章立场

## Phase 4: 结论段 (Conclusion)

**Purpose**: 撰写结论段，总结论证、重述论点、给出启示

- [ ] T017 撰写论证回顾（1-2 句）：概括全文论证链条，不做逐段复述
- [ ] T018 撰写论点重述（1 句）：用不同于引言的方式重申核心论点
- [ ] T019 撰写延伸思考（1-2 句）：论点成立后的启示或行动建议——必须与核心论点直接逻辑关联
- [ ] T020 自检结论段：无新论证要点？无自谦语？读者只看引言+结论能否把握主旨？
- [ ] T021 将结论段追加写入 `dist/article/[标题].md`

**Checkpoint**: 完整文章草稿完成

---

## Phase 5: 润色与校验 (Polish & Validation)

**Purpose**: 整体通读、打磨和最终质量检查

- [ ] T022 整体通读全文，标注逻辑跳跃或过渡生硬处
- [ ] T023 [P] 检查前后论点一致性——引言论点 vs 结论重述是否一致
- [ ] T024 [P] 全文引用格式统一：确保引用风格一致（学术/大众/社交媒体格式）
- [ ] T025 [P] 引用准确性抽查：验证 30%-50% 的引用（优先核心论证要点引用）
- [ ] T026 字数统计与规模达标检查（±20% 范围内）
- [ ] T027 冗余精简：查找可删除而不影响论证的句子或段落
- [ ] T028 [P] 术语统一检查：同一概念全文使用同一术语
- [ ] T029 [P] 语法与错别字检查
- [ ] T030 [P] 可读性评估：以目标受众身份通读，标注晦涩处
- [ ] T031 对照 spec.md 成功标准逐条自评，记录不达标项
- [ ] T032 更新 `dist/article/[标题].md` 的 YAML 元数据（words、paragraphs、citations、updated）

**Checkpoint**: 文章完成，可交付审查

## Dependencies & Execution Order

### Phase Dependencies

- **准备 (Phase 1)**: 无依赖——可立即开始
- **引言 (Phase 2)**: 依赖 Phase 1 引用就位——可部分并行（引用验证与引言撰写可同时进行）
- **主体段落 (Phase 3)**: 依赖 Phase 2 引言完成（需要论点锚点）——**必须按段落顺序执行，不可乱序**
- **结论 (Phase 4)**: 依赖 Phase 3 所有主体段落完成
- **润色 (Phase 5)**: 依赖 Phase 4 结论段完成

### Within Body Phase

- 正文段落必须按论证链顺序执行（T012 → T013 → T014 ...）
- 同一论证要点的多个段落：主题段落先于展开段落
- 前一段落完成并自检通过后，方可开始下一段落

### Parallel Opportunities

- Phase 1 内所有标记 [P] 的任务可并行
- Phase 5 内所有标记 [P] 的任务可并行
- 引用检索（T001-T003）可在准备阶段批量并行执行

---

## Implementation Strategy

### Incremental Writing

1. 完成 Phase 1: 引用材料就位
2. 完成 Phase 2: 引言段定稿 → **论点锚点确立**
3. 逐段完成 Phase 3: 每完成一段，回读前一段验证过渡 → **论证链逐步构建**
4. 完成 Phase 4: 结论段定稿 → **全文闭环**
5. 执行 Phase 5: 全面打磨 → **交付审查**

### MVP 策略（论证要点 1）

若需快速验证核心论证价值，可先行完成：
- 引用针对论证要点 1 的材料检索
- 引言段 + 论证要点 1 的主体段落 + 简化结论
- 验证：仅凭论证要点 1 是否已能独立说明核心论点的基本方向？

---

## Notes

- [P] 任务 = 无相互依赖，可并行执行
- 主体段落（BODY 阶段）必须按论证链顺序执行——前一段落完成后才能开始下一段落
- 每个段落撰写完成后立即自检——不积压问题到 Phase 5
- 引用格式在全文完成后统一（Phase 5），撰写阶段可标注临时格式
- 段落字数 ±20% 浮动可接受——不要为了凑字数注水或为了削足适履砍论证
- 成品文件更新使用增量追加方式——每次执行 implement 不覆盖已有内容
