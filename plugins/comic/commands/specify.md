# 漫画规格编写

## User Input

```text
$ARGUMENTS
```

根据用户输入创建漫画功能规格文件 `spec.md`。规格文件限定在 **WHAT（什么是目标产出）** 和 **WHY（为什么这样选择）** —— 描写故事方向、画风意图、角色目标和内容规模。**不做**分镜格数分解、不做页面布局划分、不做对白脚本编写（这些属于 plan 阶段）。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目 —— 存在 `.specforge/` 目录
2. 执行 `specforge list --detail --json` 确认当前活动 feature 和内容类型为漫画
3. 若已存在 `.specforge/constitution.md`，读取宪法确保规格与视觉原则对齐
4. 确认内容类型配置中 content_type 为 `comic`

## Outline

### 第 1 步：解析用户输入

从 `$ARGUMENTS` 中提取漫画领域的核心信息，构建 what/why 问题清单：

**故事方向**（WHAT 的一部分）：
- 故事类型：热血/悬疑/恋爱/奇幻/科幻/日常/恐怖/搞笑？
- 核心冲突：主角面临的主要矛盾是什么？
- 世界观基调：现实/架空/魔幻/未来/历史？
- 目标读者：少年/少女/青年/成人？年龄段？

**画风意图**（WHY 的一部分）：
- 风格倾向：用户是否暗示了特定画风（日系漫画/美漫/欧漫/国风/实验风格）？
- 色调取向：黑白/全彩/双色/限制色调？
- 线条风格：精细/粗粝/速写/水墨/钢笔？
- 画面密度的偏好：简洁/中等/丰富/dense？

**角色设计方向**（WHAT + WHY）：
- 主角类型和核心特征（不必精确到身形数据，指性格模板和视觉印象）
- 是否有明确的角色关系网（主角团/对手/导师/伙伴）？

**内容规模**：
- 是否有明确的页数、话数预期？

若输入为空 → **ERROR**：提示提供漫画描述，例如 "日系少年热血漫画，讲述一个普通高中生意外获得时间暂停能力后的冒险故事，整体偏暖色调，线条简洁有力"

若输入信息不足，**主动提问**（最多 5 个问题），使用多重选择方式引导：
1. 画风倾向：日系少年/日系少女/美漫/欧漫/国风写实/水墨/极简实验？
2. 色调：黑白/全彩暖色/全彩冷色/限制色板（限制 3-5 色）？
3. 目标读者年龄层：少年（12-18）/青年（18-25）/成人（25+）？
4. 预期总规模：短篇（1-3 话/<100 页）/中篇（5-15 话/200-500 页）/长篇（20+话/800+页）？
5. 叙事节奏倾向：快节奏/事件驱动 或 慢节奏/角色驱动？

### 第 2 步：创建 feature 目录

- 执行 `specforge new "$DESC" --dry-run --json` 预览名称和路径
- 解析 JSON 输出确认命名合理性，若不满意提供 `--short-name` 修改选项
- 执行 `specforge new "$DESC" --json` 创建 feature
- 从 JSON 输出获取 FEATURE_DIR、FEATURE_SPEC 等路径
- 若目录已存在 → **ERROR** 提示使用不同描述或手动指定短名

### 第 3 步：加载漫画 spec 模板

- 读取 `plugins/comic/templates/spec.md` 获取模板结构
- 确认模板包含以下 what/why 字段章节：
  - `故事大纲`
  - `内容规模`（总页数 / 话数 / 每话页数范围）
  - `画风方向`（风格 / 色调 / 线条风格）
  - `角色设计目标`（表格：角色 / 身份 / 外貌特征 / 性格内核 / 叙事功能）
  - `叙事单元`（Visual Story Beat，含 Why This Priority / Independent Test / Given-When-Then，最少 2 个）
  - `成功标准`
- 确认模板 **不含** 分镜格数、页面布局、对白脚本等 plan 级字段
- 若模板缺失漫画专用章节，基于 `contracts/artifact-template.md` 补充

### 第 4 步：编写故事大纲

- 用 100-200 字概括核心情节
- 结构：开端（设定引入与冲突起点）→ 发展（主要冲突展开）→ 转折（关键剧情节点）→ 高潮（情感/动作顶峰）→ 结局（收束或悬念）
- 保持 what/why 视角：只描述"故事要讲什么"和"为什么选择这个叙事方向"，不描述"每页/每话怎么画"
- 大纲需体现与画风意图的一致性——如黑暗悬疑故事不应搭配明亮卡通风

### 第 5 步：定义画风方向

从用户输入中提炼并结构化画风方向，每个维度含 WHY 解释：

- **整体风格**（WHAT）：写实 / 卡通 / 水墨 / 日系少年 / 日系少女 / 美漫 / 欧漫 / 实验 —— 明确指定
- **色调**（WHAT）：黑白 / 全彩暖色 / 全彩冷色 / 限制色板 [列出具体色] / 水墨 —— 明确指定
- **线条风格**（WHAT）：精细钢笔画 / 粗粝毛笔 / 速写风 / 数码平滑 / 铅笔感 —— 明确指定
- **画面密度**（WHAT）：简洁（少背景、大画框）/ 中等（常规场景+背景）/ 高密度（繁复背景+细节丰富）
- **每种选择的 WHY**：说明为什么这个画风适合这个故事和目标读者（如"粗粝线条适配末日题材的粗粝感，精细线条适合表达角色细腻心理"）

### 第 6 步：设计角色目标

创建角色设计目标表，至少 3 个角色。每行为一个角色：

| 角色 | 身份 | 外貌特征 | 性格内核 | 叙事功能 |
|------|------|---------|---------|---------|
| [角色名] | [在故事中的身份] | [视觉辨识特征，如发型、体型、标志服饰/配件] | [核心性格特质 1-2 条] | [在故事中的叙事功能，如"主角——推动主线"、"导师——提供关键信息"] |

- 角色的外貌特征仅描述 **视觉设计目标**（如"尖下巴、冷峻眼神"），不做实际设计稿
- 叙事功能说明 WHY 这个角色对故事必要（避免可有可无的装饰性角色）
- 若用户未提供足够角色，基于故事类型给出 3 个建议角色并标注"建议" → 引导用户确认或调整

### 第 7 步：设定内容规模

独立「内容规模」章节，定义：

- **总页数**：[预估总页数]（含封面/内封/目录/正文/后记）
- **话数**：[话/章数量]
- **每话页数范围**：[下限 — 上限] 页/话（说明范围依据，如"少年周刊标准 18-22 页/话"）

⚠️ 此处**不分解**每话几页几个分镜 —— 那是 plan 阶段的工作。

### 第 8 步：定义叙事单元（Visual Story Beat）

漫画特有的领域化 User Story 结构。最少 2 个，每个含：

```
### 叙事单元 N - [单元标题] (Priority: P[N])

[描述这个视觉叙事单元 —— 在整体故事中的位置、覆盖的情节范围、要达到的视觉-情感效果。一篇完整叙事单元可以跨多页/多分镜，但不在此定义具体格数。]

**Why this priority**: [解释为什么这个叙事单元对整个漫画最核心 —— 是角色转折点？世界观揭示？情感高潮？还是视觉奇观段落？]

**Independent Test**: [如何独立验证 —— 例如 "阅读该单元的完整分镜后，能独立判断情绪传达是否达成预期，无需依赖前后单元" 或 "单独抽取本单元的画稿，能通过画面连贯性判断叙事质量"]

**Acceptance Scenarios**:

1. **Given** [前一叙事单元建立的情绪/信息状态]，
   **When** [本单元的关键视觉动作/画面切换——如从平静到战斗、从对话到沉默、从外景到内心画面]，
   **Then** [读者应感受到的视觉冲击/情感变化/信息获得——如 "感受到角色内心的愤怒与无助" "理解世界观的核心规则"]

2. **Given** [另一状态]，
   **When** [另一视觉动作]，
   **Then** [另一预期效果]
```

叙事单元的选择需覆盖故事的关键节点 —— 如序章/情感转折/高潮/结局。**不在此处指定每个单元的分镜数量**。

### 第 9 步：定义成功标准

列出可衡量的成功指标，使用 SC-### 编号：

- **SC-001 叙事传达力**：[如 "90% 试读者能在无对白辅助情况下理解各叙事单元的核心情绪"]
- **SC-002 视觉辨识度**：[如 "每个主要角色在只看剪影的情况下能被辨识"]
- **SC-003 画风一致性**：[如 "任意抽取 10 页，色调和线条风格偏差在可控范围内"]
- **SC-004 体量达标**：[如 "最终产出总页数在目标 ±10% 范围内"]
- **SC-005 读者反馈**：[如 "目标读者群体中 ≥80% 表示'愿意继续阅读下一话'"]

### 第 10 步：写入 spec 文件

- 使用加载的漫画 spec 模板，将第 4-9 步的生成内容填充
- 写入 `FEATURE_DIR/spec.md`
- 确认所有占位符 `[PLACEHOLDER]` 已被替换
- 确认 **不含** 分镜格数、页面布局、对白脚本等内容（这些属于 plan）
- 确认内容规模章节包含总页数、话数、每话页数范围三个字段

## Output

- **制品**：`FEATURE_DIR/spec.md`
- **格式**：Markdown
- **内容章节**：故事大纲 → 内容规模 → 画风方向 → 角色设计目标 → 叙事单元（≥2 个，含 Why Priority + Independent Test + Given-When-Then）→ 成功标准

## Stage Checkpoints

- [ ] 故事大纲含 100-200 字核心情节概括
- [ ] 画风方向含整体风格 + 色调 + 线条风格 + 画面密度，每个有 WHY 说明
- [ ] 角色设计目标表含 ≥3 个角色，每行含外貌特征、性格内核、叙事功能
- [ ] 内容规模包含总页数 + 话数 + 每话页数范围
- [ ] 叙事单元 ≥2 个，每个含 Why This Priority / Independent Test / Given-When-Then
- [ ] 成功标准 ≥3 条，含 SC-### 编号
- [ ] **合规检查**：spec 中不含分镜格数、不含页面布局、不含对白脚本、不含章节拆分、不含每话页数分解
- [ ] 无模糊占位符残留

## 质量门禁

- 画风方向的每个维度选择是否有明确的 WHY（不仅仅是"因为好看"）？
- 角色设计目标表中每个角色是否有清晰的叙事功能（不只是"出场人物"）？
- 叙事单元的 Acceptance Scenarios 是否能独立验证（不依赖未定义的下游产出）？
- 内容规模的数值是否有依据（市场惯例/故事需求/用户明确目标）？
- **作用域验证**：全文搜索 `分镜|格数|页面布局|对白写法|每页几格` 等 plan 阶段术语，出现即为违规

**下一步**：执行 `/specforge.clarify` 澄清歧义，或直接进入 `/specforge.plan` 制定创作计划
