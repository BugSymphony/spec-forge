# 漫画创作实现

## User Input

```text
$ARGUMENTS
```

根据 tasks.md 中定义的任务顺序，逐步执行漫画创作实现。产出为 `dist/comic/` 目录下的每话脚本文件和角色参考文件，可作为下游 AI 图像生成工具的输入。

## Pre-Execution Checks

1. 确认 `.specforge/` 存在，当前项目为漫画类型
2. 执行 `specforge list --detail --json` 确认活动 feature
3. 执行 `specforge show --artifact tasks` 加载 tasks.md，确认任务清单完整
4. 执行 `specforge validate --stage tasks --json` 验证任务阶段就绪
5. 确认 `FEATURE_DIR/plan.md` 包含完整的分镜排列、页面布局和对白时序
6. 确认 `FEATURE_DIR/build/人物设计稿.md`、`FEATURE_DIR/build/分镜草图规划.md`、`FEATURE_DIR/build/画风参考板.md` 存在
7. 若前置文件不完整 → **ERROR** 提示执行上游阶段（specify → plan → tasks）

## Outline

### 第 1 步：确认输出目录

- 检查项目根目录下 `dist/comic/` 是否存在
- 若不存在，创建 `dist/comic/` 目录
- 若已存在，检查已有文件 → 采用增量模式：只生成 tasks.md 中标记为未完成 `[ ]` 的话数，不覆盖已有脚本

### 第 2 步：加载所有创作资产

读取以下文件建立完整的创作上下文：

- **FEATURE_DIR/spec.md**：故事大纲、画风方向、角色设计目标、成功标准
- **FEATURE_DIR/plan.md**：分镜排列、页面布局、对白时序、宪法检查
- **FEATURE_DIR/tasks.md**：任务执行顺序和完成状态
- **build/人物设计稿.md**：角色视觉规格（正面/侧面/背面/表情集/服饰/道具）
- **build/分镜草图规划.md**：`[话]-[页]-[格]` 索引 + 构图/视角/运动线
- **build/画风参考板.md**：色调板、线条规范、网点/阴影风格

### 第 3 步：按话循环执行（逐话生成）

对 tasks.md 中标记为 `[ ]` 的每话任务，按优先级顺序执行：

```
for each 话 in plan.md 分镜排列:
    1. 读取该话在 plan.md 中的完整分镜排列（每页每格）
    2. 读取 build/分镜草图规划.md 中该话的构图/视角/运动线信息
    3. 生成第N话-脚本.md
    4. 生成第N话-角色参考.md（仅当该话有新角色出现或角色服饰变化时）
    5. 在 tasks.md 中标记该话任务为 [x]
```

### 第 4 步：生成第N话-脚本.md

脚本文件的详细结构（供 AI 图像生成使用）：

```markdown
# 第 [N] 话脚本：[话标题]

## 本话信息
- **总页数**: [页数]
- **情绪曲线**: [描述本话的情绪起伏，如 "开场平缓 → 第3页冲突爆发 → 第6页高潮 → 第8页悬念收束"]
- **画风参数**:
  - 线条粗细: [参照 build/画风参考板.md]
  - 色调模式: [全彩暖色/黑白/限制色板...]
  - 灰度层级: [如 4 阶：100%/75%/50%/25%]
  - 网点风格: [如 标准灰网/排线/无网点]

## 本话出场角色
| 角色 | 本话状态 | 服饰特殊说明 |
|------|---------|------------|
| [角色A] | [首次出场/继续/本话退场] | [如有换装/受伤/变形，注明] |

## 分镜脚本

### 第 1 页
**类型**: [开场/过渡/高潮/收束]
**布局**: [ASCII 格位分布]
**视线流**: [→ 箭头指示读者视线路径]

#### 格 1
- **画面描述**: [具体的画面内容 —— 人物+动作+背景+构图]
- **视角**: [平视/仰视/俯视/鸟瞰/主观视角]
- **景别**: [远景/全景/中景/近景/特写/大特写]
- **运动线**: [如 "角色A → 右方跃出画框"]
- **情绪基调**: [紧张/平静/悲伤/兴奋/...]
- **对白**:
  - [角色A]：[对白内容] `[OS]`（若为框外音）
  - [角色B]：[对白内容]
- **声效**: [如有音效文字，注明位置和样式，如 "ドン!!（画面左下 炸裂效果）"]
- **AI 生成提示**:
  - 正面提示: [描述要生成的内容 —— 角色、动作、背景、构图、风格]
  - 负面提示: [要避免的 —— 如 "变形手指、空白眼、多余肢体、画风崩坏"]
- **关键检查点**: [该格最需注意的品质点 —— 如 "角色B的面部表情必须表达惊讶"]

#### 格 2
[... 同上格式，直到该页所有格]

---

### 第 2 页
[... 循环直到本话所有页所有格]
```

每格脚本的 **AI 生成提示** 需从以下来源推导：
- 画面描述 → 来自 plan.md 分镜排列中的 `[画面内容/动作]`
- 构图方式 + 视角 → 来自 build/分镜草图规划.md
- 角色外观 → 来自 build/人物设计稿.md
- 画风参数 → 来自 build/画风参考板.md

### 第 5 步：生成第N话-角色参考.md

当该话有角色变化时，生成角色参考文件：

```markdown
# 第 [N] 话角色参考

## 角色一：[角色名]
- **本话状态**: [正常/受伤/变装/变身/年龄变化]
- **三视图变化**: [如在特定页出现特殊角度或透视，注明页-格]
- **关键表情**: [该话中使用的表情描述]
- **服饰细节**:
  - 正面: [服装描述 + 参考页-格]
  - 背面: [同上]
  - 特殊配件: [武器/道具/饰品的当前状态]
- **颜色确认**:
  - 发色: [颜色值或描述]
  - 瞳色: [颜色值或描述]
  - 肤色: [颜色值或描述]
  - 主服装色: [颜色值或描述]
- **与其他角色的身高对比**: [相对数据，如 "比角色B高 1/3 头"]

## 角色二：[角色名]
[... 同上]
```

若该话无角色变化（全部角色外观与前一话一致），则生成简化版：

```markdown
# 第 [N] 话角色参考

本话无角色外观变化。所有角色参照 `第 [N-1] 话-角色参考.md`。
如有新角色或服饰变化，请更新此文件。
```

### 第 6 步：写入 dist/ 并更新 tasks.md

- 写入 `dist/comic/第N话-脚本.md`
- 写入 `dist/comic/第N话-角色参考.md`
- 在 `FEATURE_DIR/tasks.md` 中将该话对应的任务标记为 `[x]`
- 若 tasks.md 中使用了 `[话N-页M-格K]` 粒度，逐格标记完成

**不覆盖已有文件**：若 `dist/comic/第N话-脚本.md` 已存在，仅在 tasks.md 中标记为 `[x]`，不修改文件内容（避免损坏已通过审查的成果）。

### 第 7 步：循环完所有话后的收尾

- 确认 tasks.md 中所有漫画任务标记为 `[x]`
- 生成 `dist/comic/README.md`（包含文件索引和下游使用说明）：

```markdown
# comic 输出目录

## 文件索引
| 文件 | 页数 | 格数 | 状态 |
|------|------|------|------|
| 第1话-脚本.md | [N] | [M] | 完成 |
| 第1话-角色参考.md | — | — | 完成 |

## 下游使用说明
- `第N话-脚本.md` 中的 [AI 生成提示] 节可直接作为 Stable Diffusion / Midjourney / DALL-E 等工具的 prompt 输入
- 推荐先使用 [正面提示] 生成线稿，再使用 [上色提示] 进行彩色化
- 角色一致性参考使用 `第N话-角色参考.md` 中的颜色确认表
- 分镜拼接/排列由计划中的 [页面布局] ASCII 图指导
```

## Output

- **主要产出**：`dist/comic/第N话-脚本.md`（每话一个）
- **辅助产出**：`dist/comic/第N话-角色参考.md`（每话一个）
- **目录索引**：`dist/comic/README.md`
- **状态更新**：`FEATURE_DIR/tasks.md` 中对应任务标记 `[x]`

## Stage Checkpoints

- [ ] dist/comic/ 目录已创建
- [ ] 每话的脚本文件包含完整的分镜信息（画面描述 / 视角 / 景别 / 对白 / AI 生成提示）
- [ ] 每格含 AI 生成提示的正面提示和负面提示
- [ ] 每话的角色参考文件包含颜色确认表
- [ ] 所有输出文件格式符合 Markdown 规范
- [ ] tasks.md 中所有相关任务标记为 `[x]`
- [ ] 新增文件不与已有文件冲突（增量模式）
- [ ] README.md 含文件索引和下游使用说明

## 质量门禁

- 每格脚本的 AI 生成提示是否从 plan.md 和 build/ 设计文档中正确推导（不自创信息）？
- 角色参考文件的颜色信息和外形描述是否与 build/人物设计稿.md 一致？
- 有无分镜脚本中的角色动作与 spec.md 中角色性格内核矛盾？
- 对白内容是否与 spec.md 的叙事单元情绪目标对齐？

**下一步**：执行 `/specforge.review` 审查漫画成品的视觉一致性和叙事连贯性
