# 漫画宪法管理

## User Input

```text
$ARGUMENTS
```

根据用户输入创建或修改 `.specforge/constitution.md` 宪法文件。漫画宪法定义了视觉叙事和画面品质的核心原则，作为后续分镜设计、画风方向、角色创作的约束基准。所有 SDD 阶段命令必须遵循宪法约束。

## Pre-Execution Checks

1. 确认当前目录为 SpecForge 项目 —— 存在 `.specforge/` 目录
2. 执行 `specforge list --detail --json` 确认当前活动 feature 和项目上下文
3. 读取 `.specforge/templates/constitution-template.md` 获取输出结构模板
4. 检查内容类型配置，确认当前类型为漫画 `comic`
5. 若 `.specforge/constitution.md` 已存在，视为更新操作 —— 保留已有原则，仅根据用户输入调整或补充

## Outline

### 第 1 步：解析用户输入

从 `$ARGUMENTS` 中提取漫画领域关键信息：

- **视觉风格倾向**：用户是否提到特定画风（写实、卡通、水墨、日系、美系等）
- **叙事目标**：故事类型（热血、悬疑、恋爱、奇幻、日常等）和目标读者群
- **创作约束**：是否有明确的页数限制、话数规划、色彩约束（全彩/黑白/双色）
- **品质标准**：用户提到的完稿要求、精度期望、交付标准

若用户输入为空则 **ERROR**：提示提供漫画项目描述，例如 "全彩热血少年漫画，注重战斗场面的视觉冲击力与角色成长"

### 第 2 步：加载宪法模板

- 读取 `.specforge/templates/constitution-template.md` 获取结构骨架
- 确认模板包含漫画宪法的基础章节：
  - `# [项目名] 漫画创作宪法`
  - `## 视觉原则`（替代通用"核心原则"）
  - `## 叙事标准`（漫画特有）
  - `## 品质标准`
  - `## 制作规范`
  - `## 治理规则`

若模板不包含「视觉原则」和「叙事标准」章节，使用以下扩展结构填充。

### 第 3 步：定义视觉原则（最少 3 条）

引导用户定义 3-5 条视觉创作原则。每条原则含名称、描述和理由。漫画特有的引导问题：

1. **第一条原则（风格统一性）**：这个漫画最不可妥协的视觉风格特征是什么？
   - 例如：「所有角色比例必须遵循统一的头身比标准，偏差不超过 5%」
   - 例如：「背景处理必须与前景角色保持一致的线条粗细和墨量」
2. **第二条原则（画面传达力）**：每个分镜/页面必须达到的最低视觉传达标准是什么？
   - 例如：「每个分镜必须清晰传达情绪，读者无需文字即可理解角色状态」
   - 例如：「动作场景的分镜必须确保运动方向一致，禁止方向跳跃」
3. **第三条原则（质量标准）**：画面完稿的最低品质门槛是什么？
   - 例如：「线稿闭合度 ≥95%，上色区域不得越界」
   - 例如：「所有角色在每一话中的外貌特征（发型、服饰、标志物）必须一致」
4. **第四条原则（可选，读者引导）**：对读者视觉体验的承诺——如视线引导原则、翻页悬念设计
5. **第五条原则（可选，协作约束）**：多创作者时的统一规范（如命名规范、图层管理、网格系统）

每条原则的 **理由** 需要说明违反该原则对漫画品质的具体影响（如"风格不统一会导致读者认知中断，降低沉浸感"）。

### 第 4 步：定义叙事标准（最少 3 条）

漫画叙事的独特约束：

1. **视点一致性**：跨分镜/跨页面的叙事视点切换规则
   - 例如：「同一场景内，视点移动必须遵循 180 度线规则」
2. **节奏控制**：情感节奏与画面密度的匹配规则
   - 例如：「高潮场景每页分镜数 ≤3，日常场景每页分镜数 ≤6」
3. **对白-画面关系**：文字与画面的主从关系
   - 例如：「画面优先原则——能用画面传达的信息不用对白重复，对白仅用于画面无法传达的内心独白/关键信息」
4. **情绪曲线**：故事整体情绪起伏的设计约束
   - 例如：「每话必须包含至少 1 个情绪高点，且高点前必须有至少 2 页的情绪铺垫」

每条叙事标准同样需要 **理由**，解释对读者阅读体验的必要性。

### 第 5 步：定义品质标准

列出适用于漫画 SDD 阶段制品的质量检查维度，使用 QS-### 编号：

- **QS-001 完整性**：所有必填字段均已填写，无空占位符，角色设计表完整
- **QS-002 一致性**：spec/plan/tasks 间无矛盾，角色名称/特征描述前后一致
- **QS-003 可执行性**：任务描述具体到可执行程度，含明确分镜/页面的产出标准
- **QS-004 清晰性**：画风描述有具体参照（如"类似 XX 作品XX 章节的画风"），避免纯抽象形容词
- **QS-005 画面连贯性**：角色设计表在每一话中一致使用，分镜过渡符合视觉规律
- **QS-006 对白可读性**：对白长度适配画框空间，语气符合角色性格，无语病
- **QS-007 叙事节奏**：分镜密度分布合理，情绪曲线符合故事类型预期

### 第 6 步：定义制作规范

漫画特有的制作约束：

- **网格系统**：页面基础网格类型（如「单页 3×3 9 格基础，可合并」）
- **输出格式**：稿纸尺寸、分辨率（dpi）、出血设置、色彩模式（CMYK/RGB）
- **命名规范**：角色/场景/道具的命名约定（如「角色_[名称]_[角度]_v[N].psd」）
- **分层规范**：线稿层、上色层、对白层、效果层的命名和顺序约定
- **审查流程**：线稿审查 → 上色审查 → 对白审查 → 成稿审查，每阶段 gate 条件

### 第 7 步：设定治理规则

**修订流程**：
1. **提议**：任何创作者可提交宪法修订提案，说明动机和影响范围
2. **审查**：首席创作（画师）评估提议的合理性和对画面一致性的影响
3. **批准**：审查通过后合并修订，更新版本号
4. **传播**：同步更新所有已产出制品中对宪法的引用，必要时回溯修正已有分镜

**版本管理**：使用 MAJOR.MINOR.PATCH 语义版本
- MAJOR：移除或重新定义核心视觉原则/叙事标准
- MINOR：新增原则或叙事标准
- PATCH：措辞澄清、示例补充

### 第 8 步：写入宪法文件

- 使用模板结构，用第 3-7 步的生成内容填充占位符
- 写入 `.specforge/constitution.md`
- 确保版本号设为 `1.0.0`，批准日期和最后修订日期为当前日期
- 若为更新操作：保留当前版本号，根据变更幅度递增
- 确保所有视觉原则和叙事标准的具体性 —— 每一条都能独立判断是否违规

## Output

- **制品**：`.specforge/constitution.md`
- **格式**：Markdown
- **位置**：项目根目录 `.specforge/constitution.md`
- **内容章节**：视觉原则（3-5 条）+ 叙事标准（3-5 条）+ 品质标准（QS-001~QS-007）+ 制作规范 + 治理规则

## Stage Checkpoints

- [ ] 至少定义 3 条视觉原则，每条有名称、描述和理由
- [ ] 至少定义 3 条叙事标准，每条有名称、描述和理由
- [ ] 品质标准包含漫画特有的 QS-005 画面连贯性、QS-006 对白可读性、QS-007 叙事节奏
- [ ] 制作规范含网格系统、输出格式、命名规范、分层规范、审查流程
- [ ] 版本号和日期已填写
- [ ] 无模糊占位符残留

## 质量门禁

- 视觉原则是否具体到可独立判断违规？（如"线条粗细一致"需量化或给出判断方法）
- 叙事标准是否覆盖视点、节奏、对白-画面关系三个核心维度？
- 制作规范是否可指导实际创作（非泛泛的"注意质量"）？
- 品质标准是否涵盖从 spec 到 dist/ 的全流程检查维度？
- 治理规则是否包含修订流程和版本管理？
