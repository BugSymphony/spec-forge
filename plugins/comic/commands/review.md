# 漫画成品审查

## User Input

```text
$ARGUMENTS
```

对 `dist/comic/` 目录下的漫画脚本进行全面的质量审查。审查维度包括：视觉一致性（角色是否变形、画风是否统一）、叙事连贯性（故事线是否完整、情绪曲线是否达标）、以及宪法对齐（是否遵守视觉原则和叙事标准）。

## Pre-Execution Checks

1. 确认 `.specforge/` 存在，当前项目为漫画类型
2. 执行 `specforge list --detail --json` 确认活动 feature
3. 执行 `specforge show --artifact spec` 加载 spec.md（成功标准对照）
4. 确认 `.specforge/constitution.md` 存在（宪法对照）
5. 确认 `dist/comic/` 目录存在且包含至少一个脚本文件
6. 若 dist/comic/ 为空 → **ERROR** 提示先执行 `/specforge.implement` 完成创作

## Outline

### 第 1 步：加载审查基准

加载以下文件作为审查基准：

- **spec.md**：故事大纲、画风方向、角色设计目标、成功标准（SC-001 ~ SC-005）
- **plan.md**：分镜排列、页面布局、对白时序
- **.specforge/constitution.md**：视觉原则、叙事标准、品质标准
- **build/人物设计稿.md**：角色视觉规格
- **build/画风参考板.md**：色调板、线条规范

### 第 2 步：视觉一致性审计

逐话检查 dist/comic/ 中所有 `第N话-脚本.md` 和 `第N话-角色参考.md` 的视觉一致性：

**角色一致性检查清单**：

| 检查项 | 标准来源 | 检查方法 |
|--------|---------|---------|
| 角色外貌（发型/瞳色/体型） | build/人物设计稿.md | 逐格对比角色描述是否与设计稿一致 |
| 角色服饰（常服/特殊服装） | build/人物设计稿.md + 角色参考.md | 检查同话内服饰描述的延续性 |
| 表情与性格匹配 | spec.md 角色设计目标的「性格内核」 | 验证每个有表情描述的分镜是否与性格一致 |
| 角色比例 | build/人物设计稿.md 的身高对比 | 检查不同角色同框时的相对比例描述 |
| 标志道具/配件 | build/人物设计稿.md | 确认使用场景正确 |

**画风一致性检查清单**：

| 检查项 | 标准来源 | 检查方法 |
|--------|---------|---------|
| 线条粗细一致性 | build/画风参考板.md | 检查各话脚本中的线条参数描述是否统一 |
| 色调模式 | build/画风参考板.md + spec.md 画风方向 | 同一部作品色调不应突变（除非剧情需要） |
| 网点/阴影风格 | build/画风参考板.md | 阶段切换需要合理叙事理由 |
| 画面密度 | spec.md 画风方向的画面密度参数 | 场景类型（日常/高潮）的画面密度是否匹配预期 |

**违规评级**：
- **BLOCKER**：角色外貌出现矛盾描述（如第 1 话说"蓝发"、第 3 话说"红发"），阻塞审查通过
- **WARNING**：色调微小偏差、线条风格轻微不一致（需要改但可以不阻塞后续）
- **INFO**：非关键的风格微调说明（作为改进建议）

### 第 3 步：叙事连贯性检查

逐话检查叙事流畅度和情绪曲线：

**故事线完整性**：

- 对照 spec.md 的故事大纲（开端→发展→转折→高潮→结局），验证分镜脚本覆盖所有节点
- 每个叙事单元的 Acceptance Scenarios（Given-When-Then）是否在对应话的分镜中得到满足？
  - 检查 Given 条件在分镜中是否建立
  - 检查 When 触发动作是否对应该叙事单元的关键画面切换
  - 检查 Then 的预期情绪效果是否在对白时序的情绪标记中得到体现

**对白连贯性检查**：

| 检查项 | 标准来源 | 检查方法 |
|--------|---------|---------|
| 角色语音一致性 | spec.md 角色性格内核 + plan.md 对白时序 | 检查同一角色的说话风格是否一致 |
| 信息密度 | plan.md 对白量分配规则 | 动作场景对白是否 ≤1 句/格，对话场景 1-3 句/格 |
| 静默使用合理性 | plan.md 对白时序的 `[无对白]` 标记 | 无声格是否有明确的静默意图 |
| 前后对白无矛盾 | 上下文对白内容 | 防止角色 B 在第 5 格不知道的信息在第 3 格已提及 |

**情绪曲线评估**：

- 根据 plan.md 每话的情绪曲线描述，重放分镜序列并评分：
  - 情绪铺垫是否足够（高潮前是否有 ≥2 页的情绪积累，参照宪法叙事标准第 4 条）
  - 情绪释放点是否在分镜密度上得到体现（高潮页分镜格数 ≤3，参照宪法叙事标准第 2 条）
  - 整话看完后的情绪残留是否符合作者意图

**违规评级**：
- **BLOCKER**：故事线断裂、关键叙事节点缺失、角色性格前后矛盾
- **WARNING**：情绪节奏偏快/偏慢、对白密度偏高（但不影响理解）
- **INFO**：可改进之处（如额外增加一页过渡可能更好）

### 第 4 步：宪法对齐审查

逐条检查 `.specforge/constitution.md` 中的原则是否在成品中贯彻：

**视觉原则对齐**：
- 逐条视觉原则 vs 分镜脚本的实际表现
- 例如：宪法规定 "所有角色比例偏差不超过 5%" → 检查角色参考文件中的描述一致性
- 例如：宪法规定 "每个分镜传达清晰情绪" → 检查 `[无对白]` 格是否有足够画面信息传达情绪

**叙事标准对齐**：
- 视点一致性：同一场景内镜头是否有跳跃（参照宪法叙事标准第 1 条）
- 对白-画面关系：是否有"用文字解释画面的内容"的冗余对白（参照宪法叙事标准第 3 条）
- 节奏控制：高潮密度和过渡密度是否符合宪法要求（参照宪法叙事标准第 2 条）

**品质标准对齐**：
- QS-005 画面连贯性：角色在跨话连续性
- QS-006 对白可读性：对白长度是否适配画框空间
- QS-007 叙事节奏：情绪曲线是否符合故事类型预期

### 第 5 步：成功标准验证

对照 spec.md 中的 SC-001 ~ SC-005 进行达标评估：

- **SC-001 叙事传达力**：逐一检查叙事单元的 Acceptance Scenarios，评估 Then 效果是否通过分镜达成
- **SC-002 视觉辨识度**：检查角色参考文件的剪影描述是否足够区分各角色
- **SC-003 画风一致性**：统计画风偏差出现次数（WARNING 以上为偏差）
- **SC-004 体量达标**：统计实际总页数是否在目标 ±10% 范围内
- **SC-005 读者反馈**：若尚未有实际读者，改为"基于分镜质量的预测性评估"

### 第 7 步：写入审查报告

- 写入 `FEATURE_DIR/review-report.md`
- 若存在 BLOCKER 项 → 在 `FEATURE_DIR/tasks.md` 中追加修复任务
- BLOCKER 项的修复需要在 tasks.md 中新建 Phase（如 Phase N: 审查修复），指向具体的 `dist/comic/第N话-脚本.md` 修复任务

## Output

- **审查报告**：`FEATURE_DIR/review-report.md`
- **格式**：Markdown（含结构化表格）
- **可能触发的下游**：tasks.md 追加修复任务（仅在发现 BLOCKER/WARNING 时）

## Stage Checkpoints

- [ ] 视觉一致性审计覆盖所有话和所有角色
- [ ] 叙事连贯性检查覆盖所有叙事单元的情绪目标验收
- [ ] 宪法对齐检查逐条完成
- [ ] 成功标准验证 5 条全部评估
- [ ] 审查报告含执行摘要、明细发现、评级和修复建议
- [ ] BLOCKER 项已关联到具体文件行级别

## 质量门禁

- 审查是否基于客观基准（spec/plan/constitution/build 文档）而非主观感受？
- 每项违规/建议是否关联到具体文件的页-格位置？
- BLOCKER 项是否有明确的修复建议和优先修复范围？
- 审查报告对修复后的成果是否提供了清晰的再审查入口？
